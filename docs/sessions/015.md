## 1. Theory — CI vs CD (20 phút)

### 1.1 Tại sao cần CI/CD

Ở Buổi 14, ta deploy bằng lệnh:

```bash
gcloud run deploy agent-api --image gcr.io/.../agent:latest --region us-central1
```

Vấn đề:

- **Manual lỗi**: người phải nhớ build, push, deploy.
- **Không có test trước deploy**: code bất lỳ push lên main có thể break production.
- **Không kiểm soát được**: ai deploy? khi nào? version nào?
- **Khó rollback**: quên lại commit hash, không thể rollback nhanh.
- **Không có audit**: không biết deploy ai, lúc nào, cái gì thay đổi.

**CI/CD giải quyết**: tự động hóa workflow sao cho mỗi push code → bắt đầu chuỗi test → build → deploy, với gate và approval.

### 1.2 Continuous Integration (CI)

CI = mỗi lần push code, tự động chạy:

```
Code Push
  ↓
Lint (code quality)
  ↓
Unit Test (fast, isolated)
  ↓
Integration Test (with DB/service)
  ↓
Agent Behavior Test (eval-like test)
  ↓
Security Test (OWASP, secrets scan)
  ↓
Build passes ✓ or fails ✗
```

Nếu fail ở bất kỳ bước nào → stop, thông báo developer.

Lợi ích: phát hiện bug sớm, ngăn code xấu merge.

### 1.3 Continuous Deployment / Continuous Delivery (CD)

**Continuous Deployment (CD)**: nếu CI pass → **tự động** deploy lên production.

**Continuous Delivery (CDE)**: nếu CI pass → sẵn sàng deploy, nhưng cần **manual approval** trước deploy.

Ta dùng **CDE + manual approval ở production** vì agent system cần người kiểm tra.

```
CI Pass ✓
  ↓
Build + Push Image
  ↓
Deploy Staging
  ↓
Smoke Test
  ↓
Manual Approval (Human Review)
  ↓
Deploy Production
  ↓
Verify Health
```

### 1.4 GitHub Actions anatomy

GitHub Actions là CI/CD platform native của GitHub. Cấu trúc:

```yaml
name: Agent CI/CD # Tên workflow

on: # Trigger
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs: # Danh sách công việc song song/tuần tự
  test: # Job ID
    runs-on: ubuntu-latest # Runner (máy chạy workflow)
    steps: # Danh sách bước trong job
      - uses: actions/checkout@v4 # Action có sẵn
      - name: Run tests # Bước tự viết
        run: pytest tests/
```

Ba khái niệm cốt lõi:

| Khái niệm | Định nghĩa                                          | Ví dụ                         |
| --------- | --------------------------------------------------- | ----------------------------- |
| Workflow  | Quy trình tự động hoàn chỉnh từ trigger đến outcome | `ci.yml`, `deploy.yml`        |
| Job       | Một phần của workflow, chạy trên một runner         | `test`, `build`, `deploy`     |
| Step      | Một lệnh hoặc action trong job                      | `npm install`, `docker build` |

## 2. Deep Dive — CI Pipeline, Environment, Secret (25 phút)

### 2.1 CI pipeline chi tiết

Mỗi bước CI cần thiết:

#### Bước 1: Lint

```yaml
- name: Lint
  run: |
    pip install flake8 black
    black --check src/
    flake8 src/ --max-line-length=100
```

Phát hiện code style, warning sớm. Nhanh (<1 phút).

#### Bước 2: Unit Test

```yaml
- name: Unit Test
  run: |
    pip install pytest pytest-cov
    pytest tests/unit/ --cov=src/ --cov-report=term
```

Test đơn lẻ, không phụ thuộc external service. Phải fast (<3 phút).

#### Bước 3: Integration Test

```yaml
- name: Start Services
  run: docker-compose -f docker-compose.test.yml up -d

- name: Integration Test
  run: pytest tests/integration/ --tb=short

- name: Stop Services
  run: docker-compose -f docker-compose.test.yml down
```

Test với DB, queue, mock API. Chậm hơn (<10 phút).

#### Bước 4: Agent Behavior Test

```yaml
- name: Agent Behavior Test
  run: |
    pytest tests/agent_behavior/ --tb=short -v
    # Test: agent chọn đúng tool, semantic correctness, không loop vô hạn
```

Giống eval, verify agent không broken. (<5 phút).

#### Bước 5: Security Test

```yaml
- name: Security Scan
  run: |
    pip install bandit
    bandit -r src/ -f json -o bandit-report.json
    # Fail nếu critical finding
```

Scan hardcoded secret, SQL injection risk, etc.

### 2.2 Environment và Secret

GitHub Actions hỗ trợ multiple environment:

```yaml
deploy_staging:
  environment: staging
  steps:
    - name: Deploy to Staging
      env:
        REGION: us-central1
        ARTIFACT_REGISTRY: gcr.io/my-project/staging
      run: gcloud run deploy agent-api --image $ARTIFACT_REGISTRY/agent:${{ github.sha }}

deploy_production:
  environment: production
  needs: deploy_staging # Chỉ chạy sau staging success
  steps:
    - name: Manual Approval Placeholder
      # Trong GitHub UI, có approval gate
    - name: Deploy to Production
      env:
        REGION: us-central1
        ARTIFACT_REGISTRY: gcr.io/my-project/prod
      run: gcloud run deploy agent-api-prod --image $ARTIFACT_REGISTRY/agent:${{ github.sha }}
```

Mỗi environment có **secret riêng**:

```yaml
env:
  GCP_PROJECT_ID: ${{ secrets.GCP_PROJECT_ID }}
  GCP_SA_KEY: ${{ secrets.GCP_SA_KEY_PROD }} # Khác secret cho staging
```

Secret được lưu ở GitHub (encrypted), không lộ trong log.

### 2.3 Artifact và Caching

**Artifact**: file output từ CI (ví dụ: coverage report, build artifact).

```yaml
- name: Upload Coverage
  uses: actions/upload-artifact@v4
  with:
    name: coverage-report
    path: coverage/
    retention-days: 30
```

**Cache**: speedup build bằng cách cache dependencies.

```yaml
- name: Cache pip packages
  uses: actions/cache@v3
  with:
    path: ~/.cache/pip
    key: ${{ runner.os }}-pip-${{ hashFiles('**/requirements.txt') }}
    restore-keys: |
      ${{ runner.os }}-pip-
```

Lần 2 build → install 5 giây thay vì 2 phút.

### 2.4 Matrix strategy

Chạy job với multiple config song song:

```yaml
test:
  strategy:
    matrix:
      python-version: ["3.10", "3.11", "3.12"]
      os: [ubuntu-latest, macos-latest]
  runs-on: ${{ matrix.os }}
  steps:
    - uses: actions/setup-python@v4
      with:
        python-version: ${{ matrix.python-version }}
    - run: pytest tests/
```

Chạy 6 job song song (3 Python version × 2 OS), phát hiện incompatibility.

## 3. Demo — Workflow Trigger & Rollback (15 phút)

### Demo flow

Instructor:

1. **Trigger CI**: Push commit có test fail → GitHub Actions automatically run CI workflow.

   ```
   Logs thể hiện:
   - Lint PASS
   - Unit Test PASS
   - Integration Test FAIL ← agent timeout
   - Workflow stopped
   ```

2. **View logs**: Click workflow run → inspect step logs (show lỗi agent timeout).

3. **Fix + Re-run**: Push fix, workflow re-trigger, pass lần 2.

4. **Auto-deploy to staging**: Vì CI pass → auto-deploy staging. Show Cloud Run revision được tạo.

5. **Smoke test**: Workflow run smoke test sau deploy.

   ```yaml
   - name: Smoke Test
     run: |
       curl -f https://agent-staging.example.com/health || exit 1
       curl -f -X POST https://agent-staging.example.com/api/agent/health \
         -H "Content-Type: application/json" -d '{"query":"hello"}' || exit 1
   ```

6. **Manual approval**: Workflow dừng ở production deployment, chờ manual approval (show GitHub UI).

7. **Approve in GitHub UI**: Click "Approve" → workflow continue, deploy production.

8. **Rollback**: Vào Cloud Run console, click "Revisions" → select previous revision → traffic 100% → revert hoàn tất.

## 4. Lab — Xây CI/CD Pipeline (50 phút)

### Lab phases

**Phase 1 (15 phút): Tạo CI workflow**

Học viên tạo file `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v4
        with:
          python-version: "3.11"
      - name: Install dependencies
        run: pip install -r requirements.txt flake8 black
      - name: Lint
        run: |
          black --check src/
          flake8 src/ --max-line-length=100

  test:
    runs-on: ubuntu-latest
    needs: lint
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v4
        with:
          python-version: "3.11"
      - name: Cache pip
        uses: actions/cache@v3
        with:
          path: ~/.cache/pip
          key: ${{ runner.os }}-pip-${{ hashFiles('**/requirements.txt') }}
      - name: Install dependencies
        run: pip install -r requirements.txt pytest pytest-cov
      - name: Unit Tests
        run: pytest tests/unit/ --cov=src/
      - name: Integration Tests
        run: pytest tests/integration/
      - name: Agent Behavior Tests
        run: pytest tests/agent_behavior/

  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v4
        with:
          python-version: "3.11"
      - name: Install bandit
        run: pip install bandit
      - name: Security Scan
        run: bandit -r src/ --severity-level high
```

Trigger: push commit → watch CI run.

**Phase 2 (15 phút): Tạo CD workflow (build + push)**

Tạo `.github/workflows/deploy.yml`:

```yaml
name: Deploy

on:
  push:
    branches: [main]
    tags: ["release-*"]
  workflow_dispatch: # Allow manual trigger

env:
  GCP_PROJECT_ID: ${{ secrets.GCP_PROJECT_ID }}
  ARTIFACT_REGISTRY: us-central1-docker.pkg.dev

jobs:
  ci:
    uses: ./.github/workflows/ci.yml # Re-use CI workflow

  build_and_push:
    needs: ci
    runs-on: ubuntu-latest
    outputs:
      image_digest: ${{ steps.image.outputs.digest }}
    steps:
      - uses: actions/checkout@v4

      - name: Set up Cloud SDK
        uses: google-github-actions/setup-gcloud@v1
        with:
          service_account_key: ${{ secrets.GCP_SA_KEY }}
          project_id: ${{ secrets.GCP_PROJECT_ID }}

      - name: Configure Docker for Artifact Registry
        run: |
          gcloud auth configure-docker ${{ env.ARTIFACT_REGISTRY }}

      - name: Build Docker image
        id: build
        run: |
          IMAGE_TAG="${{ env.ARTIFACT_REGISTRY }}/${{ env.GCP_PROJECT_ID }}/agent:${{ github.sha }}"
          docker build -t $IMAGE_TAG -t ${{ env.ARTIFACT_REGISTRY }}/${{ env.GCP_PROJECT_ID }}/agent:latest .
          echo "image=$IMAGE_TAG" >> $GITHUB_OUTPUT

      - name: Push to Artifact Registry
        run: docker push ${{ steps.build.outputs.image }}

  deploy_staging:
    needs: build_and_push
    runs-on: ubuntu-latest
    environment: staging
    steps:
      - uses: google-github-actions/setup-gcloud@v1
        with:
          service_account_key: ${{ secrets.GCP_SA_KEY_STAGING }}
          project_id: ${{ secrets.GCP_PROJECT_ID }}

      - name: Deploy to Cloud Run (Staging)
        run: |
          gcloud run deploy agent-api \
            --image ${{ needs.build_and_push.outputs.image_digest }} \
            --region us-central1 \
            --platform managed \
            --memory 2Gi \
            --timeout 3600 \
            --set-env-vars ENVIRONMENT=staging,LOG_LEVEL=debug

  smoke_test_staging:
    needs: deploy_staging
    runs-on: ubuntu-latest
    steps:
      - name: Wait for Cloud Run service
        run: sleep 10

      - name: Health Check
        run: |
          curl -f https://agent-api-staging.run.app/health || exit 1

      - name: Smoke Test API
        run: |
          curl -f -X POST https://agent-api-staging.run.app/api/agent/run \
            -H "Content-Type: application/json" \
            -d '{"query": "What is 2+2?"}' \
            -m 30 || exit 1

  deploy_production:
    needs: [build_and_push, smoke_test_staging]
    runs-on: ubuntu-latest
    environment:
      name: production
      url: https://agent-api.run.app
    steps:
      - uses: google-github-actions/setup-gcloud@v1
        with:
          service_account_key: ${{ secrets.GCP_SA_KEY_PROD }}
          project_id: ${{ secrets.GCP_PROJECT_ID }}

      - name: Deploy to Cloud Run (Production)
        run: |
          gcloud run deploy agent-api-prod \
            --image ${{ needs.build_and_push.outputs.image_digest }} \
            --region us-central1 \
            --platform managed \
            --memory 4Gi \
            --timeout 3600 \
            --set-env-vars ENVIRONMENT=production,LOG_LEVEL=info

  verify_production:
    needs: deploy_production
    runs-on: ubuntu-latest
    steps:
      - name: Verify Production
        run: |
          curl -f https://agent-api-prod.run.app/health || exit 1
```

**Phase 3 (15 phút): Test rollback**

Học viên:

1. Check current Cloud Run revision.

   ```bash
   gcloud run revisions list --service agent-api-prod --region us-central1
   ```

2. Gọi API verify it works.

3. Simulating failed deploy: modify code → push → workflow deploy failed code → manual revert.

4. Rollback via gcloud:

   ```bash
   gcloud run services update-traffic agent-api-prod \
     --to-revisions=REVISION_ID=100 \
     --region us-central1
   ```

5. Verify traffic routed back.

**Phase 4 (5 phút): Checklist**

- [ ] CI workflow lint/test/security pass.
- [ ] Docker image build & push Artifact Registry.
- [ ] Deploy staging automatic.
- [ ] Smoke test pass.
- [ ] Manual approval gate work.
- [ ] Deploy production after approval.
- [ ] Rollback via revision switch.
- [ ] Secret không lộ trong log.

## 5. Failure Mode & Diagnosis (Review segment)

### Failure 1: Credential không đúng

**Triệu chứng**: `gcloud run deploy` fail với "unauthorized" hoặc "permission denied".

**Diagnosis**:

- Check `GCP_SA_KEY` secret có đúng không.
- Verify service account IAM roles: Cloud Run Admin, Artifact Registry Writer.
- SSH vào runner (nếu có debug option) → check `gcloud auth list`.

**Fix**:

```bash
gcloud iam service-accounts add-iam-policy-binding SERVICE_ACCOUNT@PROJECT.iam.gserviceaccount.com \
  --role roles/run.admin
```

### Failure 2: Image push timeout

**Triệu chứng**: "Build phase success, push phase timeout / connection reset".

**Diagnosis**:

- Image quá lớn (>500MB) → mất time push.
- Network bị throttle.
- Registry downtime.

**Fix**:

- Optimize Docker layer, remove unused dependency.
- Add retry logic:

  ```yaml
  - name: Push with Retry
    run: |
      for i in {1..3}; do
        docker push IMAGE && break || sleep $((i * 10))
      done
  ```

### Failure 3: Deployment timeout

**Triệu chứu**: Cloud Run deploy command timeout.

**Diagnosis**:

- Cold start quá lâu (>10 phút).
- Health check fail → Cloud Run keep trying, timeout.
- Service memory insufficient → crash before serve traffic.

**Fix**:

- Increase timeout: `--timeout 600` (gcloud default 300s).
- Pre-warm service bằng scheduled job.
- Increase memory: `--memory 4Gi`.

## 6. Kết nối với Buổi 14 & 16

### Từ Buổi 14 (Deploying to Cloud)

Buổi 14 học deployment **manual**: tự gọi `gcloud run deploy`.

Buổi 15 **tự động hóa** quy trình đó thành workflow.

Công cụ như Cloud Run, Artifact Registry vẫn dùng, nhưng trigger thay vì manual.

### Chuẩn bị cho Buổi 16 (Observability)

Buổi 16 sẽ instrument CI/CD output (log, metric, trace) vào Langfuse + OpenTelemetry.

Lúc này, CI/CD pipeline log từng deployment vào observability backend, để trace end-to-end:

```
GitHub Actions Webhook
  ↓
Workflow Run (record start time, commit hash)
  ↓
Test Phase (record duration, pass/fail)
  ↓
Build Phase (record image digest)
  ↓
Deploy Phase (record revision, traffic shift)
  ↓
Smoke Test (record latency, success)
  ↓
Mark Release in Langfuse
```

## 7. Summary

| Khái niệm     | Mục đích                               | Implementation                          |
| ------------- | -------------------------------------- | --------------------------------------- |
| CI workflow   | Tự động test code mỗi push             | GitHub Actions + pytest + security scan |
| CD workflow   | Tự động build, push, deploy            | Docker + gcloud + Cloud Run             |
| Environment   | Staging/production separation          | GitHub environment + secrets            |
| Secret        | Credential management                  | GitHub secret store (encrypted)         |
| Smoke test    | Verify deployment success              | curl health check sau deploy            |
| Rollback      | Revert failed release                  | gcloud revisions traffic update         |
| Artifact      | Intermediate output (coverage, report) | GitHub artifact storage                 |
| Approval gate | Manual review trước production deploy  | GitHub environment protection rule      |

Bây giờ, mỗi push code → tự động chạy full pipeline, safe để deploy production vì có test + approval gate. Ở Buổi 16, ta sẽ observe toàn bộ pipeline này.
