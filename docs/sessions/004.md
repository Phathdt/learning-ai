## 1. Theory — Anatomy của Agent Context (20 phút)

### 1.1 Context window: tài nguyên hữu hạn

Mỗi model call có context window limit:

- **Claude 3.5 Sonnet**: 200K tokens (input), 4K tokens (output)
- **Claude 3 Opus**: 200K tokens

Context được ghi vào **input_tokens**, tính tiền theo giá/token:

- Input: ~$3 / 1M tokens (sonnet)
- Output: ~$15 / 1M tokens

**Bài toán**: với 200K tokens, phải chia sao cho:

1. System prompt (cố định, nhưng có prompt caching → rẻ hơn sau lần 1)
2. Conversation history (hội thoại user + agent trước)
3. Skills / instructions tái sử dụng
4. Retrieved knowledge (RAG, Buổi 5)
5. Tool results (từ Buổi 3)
6. Memory (long-term facts cần nhớ)
7. Runtime state (task hiện tại, variables)
8. Output budget (dành cho model trả lời)

Mọi thành phần cạnh tranh cho **200K tokens**. Thiết kế tốt là biết bỏ cái nào, giữ cái nào.

### 1.2 Anatomy của Agent Context

```text
┌─────────────────────────────────────────────────────┐
│ SYSTEM PROMPT (cố định, cached sau lần 1)           │
│ ├─ Role: "Bạn là Operations Intelligence Agent"     │

│ ├─ User preferences: "tôi thích báo cáo chi tiết"  │
│ ├─ Facts: "Project X deadline là Q4"                │
│ ├─ Episodic: "Hôm qua xử lý incident Y thế nào"     │

├─────────────────────────────────────────────────────┤
│ SKILLS (module instruction, nạp theo nhu cầu)       │

├─────────────────────────────────────────────────────┤

│ ├─ Relevant documents: top-5 semantic search        │

│ └─ Reranked: chỉ giữ thực sự liên quan              │
├─────────────────────────────────────────────────────┤

└─────────────────────────────────────────────────────┘
        ↓

        ↓

(append vào session)
```

### 1.3 Token budgeting: "bộ khung 100-50-30-20"

Một heuristic phổ biến cho 200K window, agent dài 3-5 turns:

| Phần                   | Tokens     | Tỉ lệ      | Mục đích                                    |
| ---------------------- | ---------- | ---------- | ------------------------------------------- |
| System prompt          | 2.5K       | 1%         | Role, tool instruction, policy              |
| History (conversation) | 50K        | 25%        | Messages trước đó (6-10 turns)              |
| Long-term memory       | 5K         | 2.5%       | Top-3 retrieved facts                       |
| Skills (active)        | 10K        | 5%         | 1-2 skill module, truncated                 |
| Runtime state          | 1K         | 0.5%       | Task, user_id, timestamp                    |
| Output budget          | 4K         | 2%         | Space cho model trả lời                     |
| **Unused buffer**      | **127.5K** | **63.75%** | Retrieve dữ liệu, tool results thêm tới đây |

**Luôn dành 30-40% buffer** cho:

- Tool results lớn (SQL query result, web page)
- Retrieved documents (Buổi 5)
- Dynamic state

### 1.4 Prompt engineering cho agent

System prompt production không phải "bạn là AI assistant hữu ích" (30 dòng). Nó phải có **6 phần**:

````python
SYSTEM_PROMPT = """
# 1. ROLE & CONTEXT
Bạn là Operations Intelligence Agent.
- Người dùng: Operations team
- Scope: query operational database, phân tích dữ liệu, định vị incident
- Constraint: chỉ read-only query, không được modify data

# 2. TOOL-USE INSTRUCTION
Bạn có quyền dùng các tool sau:
- search_knowledge_base(query: str): tìm kiếm long-term knowledge, returns {results: []}
- query_database(sql: str): SQL read-only, sandbox DB, returns {rows: []}
- format_report(data: list, template: str): tạo báo cáo, returns {markdown: str}

Luôn kiểm tra cú pháp trước khi gọi. Nếu SQL không hợp lệ, thực hiện:
1. Viết lại SQL hợp lệ
2. Gọi query_database lần 2
3. Nếu vẫn lỗi, báo lỗi cho user

# 3. DECISION POLICY
- Nếu user hỏi "how many", chạy query database, KHÔNG guess
- Nếu user hỏi "why", search knowledge base trước, rồi query data
- Nếu ambiguous, hỏi clarification trước khi execute
- Sau mỗi tool call, luôn verify: "kết quả này hợp lý không?"

# 4. VERIFICATION INSTRUCTION
Trước khi trả lời cuối:
1. Kiểm tra: dữ liệu có đủ trả lời toàn bộ câu hỏi?
2. Kiểm tra: con số có hợp lý (sanity check)?
3. Nếu data lớn (>100 rows): tóm tắt, highlight key findings

# 5. OUTPUT CONTRACT
Trả lời dưới dạng:
```json
{
  "answer": "Trả lời ngắn gọn",
  "supporting_data": [...],
  "confidence": "high|medium|low",
  "sources": ["tool_name", "document_id"],
  "next_step": "Recommend: ..."
}
````

# 6. FAILURE BEHAVIOR

Nếu tool failed:

- Lỗi "permission denied": báo "không có quyền truy cập dữ liệu này"
- Lỗi "timeout": "query quá lâu, hãy thu hẹp phạm vi"
- Lỗi "no results": KHÔNG guess, báo "không có dữ liệu khớp"

Nếu user hỏi không liên quan (ví dụ: "viết thơ"): từ chối ngay, gợi ý task liên quan
"""

````

**Điểm quan trọng**: mỗi phần có ý nghĩa:
- **Role**: biến model thành persona cụ thể
- **Tool-use**: mô tả tool + khi nào dùng
- **Decision policy**: quyết định logic, không phải "default behavior"
- **Verification**: explicit check trước final answer
- **Output contract**: format rõ ràng → dễ parse
- **Failure behavior**: không hallucinate, báo lỗi trung thực

### 1.5 Context selection & ordering

Không phải tất cả data đều có giá trị bằng nhau. **Prioritization**:

| Mức độ ưu tiên | Content | Luôn giữ | Cắt nếu cần |
| --- | --- | --- | --- |
| **Critical** | Current task, user_id, permissions | ✓ | ✗ |
| **High** | System prompt, last 3 turns | ✓ | ✗ (chỉ truncate) |
| **Medium** | Last 5-7 turns history | (tùy) | ✓ (trim oldest) |
| **Low** | Verbose tool results (>500 tokens) | ✗ | ✓ (summarize) |
| **Optional** | Long-term memory facts (chưa relate) | ✗ | ✓ (exclude) |

**Ordering trong prompt** (từ trên xuống):

1. System prompt (nếu chưa cache)
2. Runtime context (user_id, timestamp)
3. Most recent turn (user request hiện tại)
4. Last 3-5 prior turns (conversation history)
5. Active skills (if relevant)
6. Long-term memory (top-3 similar facts)
7. Tool results (từ turns trước)

**Tại sao order này?**
- Model "chú ý" dễ nhất ở đầu và cuối (recency bias).
- User request đặt gần cuối (giữa context vừa xong).
- System prompt cách xa lịch sử (vì nó cố định, cache).

## 2. Deep dive — Context Engineering Patterns (30 phút)

### 2.1 Context compression strategies

Khi gần hết token, có 3 chiến lược:

| Chiến lược | Cách làm | Token saving | Con | Dùng khi |
| --- | --- | --- | --- | --- |
| **Truncate** | Bỏ turn cũ nhất | 10-20% | Mất context lâu dài | Short conv (≤10 turns) |
| **Summarize** | Gọi LLM tóm tắt lịch sử | 40-60% | Gọi model thêm (cost +) | Dài hơn 15 turns |
| **Chunking** | Giữ last N turns đầy đủ, cũ hơn bỏ | 20-30% | Mất mid-term context | Realtime agent |

**Mẫu code truncate + summarize**:

```python
def compress_history(messages: list[dict], max_tokens: int = 50000, model="claude-sonnet-4-20250514") -> list[dict]:
    """Giữ dưới max_tokens, dùng truncate + optional summarize."""
    from anthropic import Anthropic

    def count_tokens(msgs):
        # Ước lượng: ~4 chars = 1 token (simplified)
        return sum(len(str(m)) for m in msgs) // 4

    # Bước 1: Giữ N turn gần nhất đầy đủ
    kept_messages = []
    for msg in reversed(messages):
        if count_tokens(kept_messages + [msg]) < max_tokens * 0.8:  # 80% budget
            kept_messages.insert(0, msg)
        else:
            break

    # Bước 2: Nếu còn turn cũ, tóm tắt
    discarded = messages[:len(messages) - len(kept_messages)]
    if discarded and len(discarded) > 1:
        client = Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY"))

        # Gọi LLM tóm tắt
        summary_prompt = f"Tóm tắt lịch sử hội thoại sau trong 2-3 câu:\n{json.dumps(discarded)}"
        summary = client.messages.create(
            model=model, max_tokens=200,
            messages=[{"role": "user", "content": summary_prompt}]
        ).content[0].text

        # Thêm tóm tắt vào đầu
        kept_messages.insert(0, {
            "role": "user",
            "content": f"[Summary of prior conversation: {summary}]"
        })

    return kept_messages
````

### 2.2 Skills: module instruction động

Skill là một "instruction block" được tái sử dụng — giống version quản lý, có phiên bản, activation logic.

**Ví dụ**:

```python
# skills.py
SKILLS = {
    "db-query": {
        "version": "1.0",
        "description": "SQL query pattern, security best practices",
        "text": """
# SKILL: Database Querying
Khi query database:
1. Luôn dùng WHERE clause, không bao giờ SELECT * toàn bộ
2. EXPLAIN plan trước khi chạy query lớn
3. Result >1000 rows → báo user "quá nhiều", offer aggregate
4. Không được CREATE/DROP/ALTER, chỉ SELECT
""",
        "tokens": 150,
        "activation": lambda task, context: "database" in task.lower() or "query" in task.lower()
    },

    "report": {
        "version": "2.1",
        "description": "Report formatting template",
        "text": """
# SKILL: Report Formatting
Structure báo cáo:
1. Executive summary (1 paragraph)
2. Key metrics (table 5-10 rows)
3. Analysis (2-3 paragraphs)
4. Recommendation
5. Source: list mọi data source
""",
        "tokens": 200,
        "activation": lambda task, context: "report" in task.lower() or context.get("format") == "report"
    }
}

def get_active_skills(task: str, context: dict, max_skill_tokens: int = 10000) -> list[str]:
    """Lọc skill nào relevant, giữ tổng token <= max_skill_tokens."""
    active = []
    total_tokens = 0

    for skill_name, skill_def in SKILLS.items():
        if skill_def["activation"](task, context):
            if total_tokens + skill_def["tokens"] <= max_skill_tokens:
                active.append(skill_def["text"])
                total_tokens += skill_def["tokens"]

    return active
```

Khi build context:

```python
# Trong context builder
active_skills = get_active_skills(task, context, max_skill_tokens=10000)
skills_text = "\n\n".join(active_skills) if active_skills else ""

messages = [
    {"role": "user", "content": f"{system_prompt}\n\n{skills_text}\n\nTask: {task}"}
]
```

**Skill versioning**: nếu `db-query` v1.0 → v2.0 (strict change):

- Chạy parallel v1.0 vs v2.0 trên eval dataset
- Nếu v2.0 tốt hơn: activate v2.0 cho new runs, resume v1.0 cho in-flight runs
- Không bao giờ switch mid-conversation (model confuse)

### 2.3 Memory: session + long-term

**Session memory** (short-term):

- Lưu trong **LangGraph state** (Buổi 2) hoặc **conversation history**
- Tồn tại 1 session, xóa khi session kết thúc
- Key: `messages` trong state

```python
class AgentState(TypedDict):
    messages: Annotated[list[dict], add]  # session memory
    task: str
    user_id: str
```

**Long-term memory** (cross-session):

- Lưu trong **database** với embedding vector
- Tồn tại lâu dài, shared giữa sessions
- Key: `(user_id, fact_id)` hoặc semantic search

```python
# long_term_memory.py
import sqlite3
from anthropic import Anthropic

class LongTermMemory:
    def __init__(self, db_path: str = "memory.db"):
        self.db_path = db_path
        self._init_db()

    def _init_db(self):
        conn = sqlite3.connect(self.db_path)
        c = conn.cursor()
        c.execute("""CREATE TABLE IF NOT EXISTS facts (
            id TEXT PRIMARY KEY,
            user_id TEXT NOT NULL,
            fact TEXT NOT NULL,
            embedding BLOB,  -- vector as binary
            timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,
            importance REAL DEFAULT 0.5,
            UNIQUE(user_id, fact)
        )""")
        conn.commit()
        conn.close()

    def write_fact(self, user_id: str, fact: str, importance: float = 0.5):
        """Ghi một fact vào long-term memory."""
        # Nếu fact tương tự đã có → update importance, không duplicate
        similar = self.search_similar(user_id, fact, threshold=0.9)
        if similar:
            # Update existing fact
            fact_id = similar[0]["id"]
            conn = sqlite3.connect(self.db_path)
            c = conn.cursor()
            c.execute("UPDATE facts SET importance = MAX(importance, ?) WHERE id = ?",
                     (importance, fact_id))
            conn.commit()
            conn.close()
            return

        # Lệnh mới: embed + write
        fact_id = f"{user_id}:{len(fact)}"
        # TODO: embed fact (sẽ làm ở Buổi 5)

        conn = sqlite3.connect(self.db_path)
        c = conn.cursor()
        c.execute("INSERT INTO facts (id, user_id, fact, importance) VALUES (?, ?, ?, ?)",
                 (fact_id, user_id, fact, importance))
        conn.commit()
        conn.close()

    def search_similar(self, user_id: str, query: str, threshold: float = 0.7, top_k: int = 3):
        """Tìm fact tương tự (semantic search, Buổi 5)."""
        # TODO: implement khi có embedding
        # For now, simple substring match
        conn = sqlite3.connect(self.db_path)
        c = conn.cursor()
        c.execute("""SELECT id, fact, importance FROM facts
                     WHERE user_id = ? AND fact LIKE ?
                     ORDER BY importance DESC LIMIT ?""",
                 (user_id, f"%{query[:20]}%", top_k))
        results = [{"id": r[0], "fact": r[1], "importance": r[2]} for r in c.fetchall()]
        conn.close()
        return results

    def delete_fact(self, fact_id: str):
        """Xóa fact (correction)."""
        conn = sqlite3.connect(self.db_path)
        c = conn.cursor()
        c.execute("DELETE FROM facts WHERE id = ?", (fact_id,))
        conn.commit()
        conn.close()
```

**Memory write policy**: khi nên ghi?

- ✓ Ghi: "User prefer JSON format" (preference)
- ✓ Ghi: "Project X deadline is Q4" (fact)
- ✗ Không ghi: "search query was 'abc'" (ephemeral)
- ✗ Không ghi: tool error messages (noise)

### 2.4 User namespace isolation

Multi-user system cần isolation cặn kẽ. **Checklist**:

```python
# context_builder.py
def build_context(task: str, user_id: str, tenant_id: str) -> dict:
    """Build context with isolation checks."""

    # BOUNDARY 1: Check permission
    if not has_permission(user_id, "operations"):
        raise PermissionError(f"User {user_id} not allowed")

    # BOUNDARY 2: Load session memory ONLY for this user
    messages = get_session_messages(user_id=user_id)  # ← WHERE user_id = ?

    # BOUNDARY 3: Load long-term memory ONLY for this user
    long_term = memory.search_similar(user_id=user_id, query=task)  # ← WHERE user_id = ?

    # BOUNDARY 4: Load skills (shared, not per-user)
    skills = get_active_skills(task, tenant_id=tenant_id)  # ← skill base on tenant role

    # BOUNDARY 5: Runtime state tagged with user_id
    runtime = {
        "user_id": user_id,  # ← pass to every tool call
        "tenant_id": tenant_id,
        "request_id": uuid.uuid4(),
        "timestamp": datetime.now(),
    }

    context = {
        "messages": messages,
        "long_term_facts": long_term,
        "skills": skills,
        "runtime": runtime,
    }

    return context
```

## 3. Demo — Instructor (15 phút)

### Demo code: context_builder_with_budget.py

```python
# demo_context_builder.py
import os, json
import tiktoken
from anthropic import Anthropic
from typing import TypedDict

client = Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY"))
MODEL = "claude-sonnet-4-20250514"
TOKEN_LIMIT = 200000
OUTPUT_BUFFER = 4000

# Token budget allocation
TOKEN_BUDGET = {
    "system_prompt": 2500,
    "history": 50000,
    "long_term_memory": 5000,
    "skills": 10000,
    "runtime_state": 1000,
    "buffer": TOKEN_LIMIT - 2500 - 50000 - 5000 - 10000 - 1000 - OUTPUT_BUFFER,
}

SYSTEM_PROMPT = """Bạn là Operations Intelligence Agent.
- Dùng tool để trả lời chính xác
- Nếu không chắc: hỏi clarification
- Luôn verify kết quả trước trả lời cuối"""

SKILLS_LIBRARY = {
    "db-query": """# SKILL: Database Querying
- Luôn WHERE clause
- Aggregate nếu >100 rows
- EXPLAIN trước""",

    "report": """# SKILL: Report
1. Summary
2. Metrics
3. Analysis
4. Recommendation""",
}

def count_tokens(text: str, model: str = "claude-3-5-sonnet-20241022") -> int:
    """Đếm token dùng tiktoken."""
    enc = tiktoken.encoding_for_model(model)
    return len(enc.encode(text))

def select_skills(task: str, max_tokens: int) -> str:
    """Lọc skill theo task, giữ tổng ≤ max_tokens."""
    active = []
    total = 0

    keywords = {
        "db-query": ["query", "database", "sql"],
        "report": ["report", "summary", "metrics"],
    }

    for skill_name, keywords_list in keywords.items():
        if any(kw in task.lower() for kw in keywords_list):
            skill_text = SKILLS_LIBRARY[skill_name]
            tokens = count_tokens(skill_text)
            if total + tokens <= max_tokens:
                active.append(skill_text)
                total += tokens

    return "\n\n".join(active)

def compress_history(messages: list[dict], max_tokens: int) -> list[dict]:
    """Trim history để ≤ max_tokens."""
    kept = []
    total = 0

    for msg in reversed(messages):
        msg_tokens = count_tokens(json.dumps(msg))
        if total + msg_tokens <= max_tokens:
            kept.insert(0, msg)
            total += msg_tokens
        else:
            break

    return kept

def build_context(task: str, history: list[dict], long_term_facts: list[str], user_id: str = "user_1"):
    """Build context với token budget."""

    # 1. System prompt
    system_tokens = count_tokens(SYSTEM_PROMPT)
    print(f"System prompt: {system_tokens} tokens")

    # 2. Runtime state
    runtime_json = json.dumps({
        "user_id": user_id,
        "task": task,
        "timestamp": "2026-09-27T10:00:00Z"
    })
    runtime_tokens = count_tokens(runtime_json)
    print(f"Runtime state: {runtime_tokens} tokens")

    # 3. Long-term memory
    long_term_text = "\n".join(f"- {fact}" for fact in long_term_facts)
    long_term_tokens = count_tokens(long_term_text)
    used_long_term = min(long_term_tokens, TOKEN_BUDGET["long_term_memory"])
    print(f"Long-term memory: {used_long_term}/{long_term_tokens} tokens")

    # 4. Skills
    skills_text = select_skills(task, TOKEN_BUDGET["skills"])
    skills_tokens = count_tokens(skills_text)
    print(f"Skills: {skills_tokens} tokens")

    # 5. History (compress if needed)
    history_budget = TOKEN_BUDGET["history"]
    history_compressed = compress_history(history, history_budget)
    history_tokens = count_tokens(json.dumps(history_compressed))
    print(f"History: {history_tokens}/{history_budget} tokens ({len(history_compressed)} messages)")

    # 6. Sanity check
    total_used = system_tokens + runtime_tokens + used_long_term + skills_tokens + history_tokens
    print(f"\nTotal used: {total_used} / {TOKEN_LIMIT} tokens ({100 * total_used // TOKEN_LIMIT}%)")
    print(f"Available for tool results: {TOKEN_LIMIT - total_used - OUTPUT_BUFFER} tokens")

    # Build final prompt
    context_parts = [SYSTEM_PROMPT]
    if long_term_text:
        context_parts.append(f"## Long-term facts\n{long_term_text}")
    if skills_text:
        context_parts.append(f"## Skills\n{skills_text}")
    context_parts.append(f"## Runtime\n{runtime_json}")

    full_prompt = "\n\n".join(context_parts)

    return {
        "system_prompt": SYSTEM_PROMPT,
        "context": full_prompt,
        "messages": history_compressed,
        "token_budget_usage": {
            "system": system_tokens,
            "runtime": runtime_tokens,
            "long_term": used_long_term,
            "skills": skills_tokens,
            "history": history_tokens,
            "total": total_used,
        }
    }

# Demo
if __name__ == "__main__":
    task = "Analyze Q3 revenue drop and suggest recovery plan. Format as report."
```

## 4. Lab — Build Context Pipeline (45 phút)

### 4.1 Bài tập chính

**Mục tiêu**: xây context builder tích hợp vào agent loop từ Buổi 2. Bổ sung:

- Token budget chia động
- Skill loading (db-query, report)
- Session memory (messages)
- Long-term memory (facts + search)
- Multi-user isolation

### 4.2 Skeleton code

```python
# lab_context_builder.py
import os, json, sqlite3, uuid
from typing import TypedDict, Annotated
from operator import add
from anthropic import Anthropic
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.sqlite import SqliteSaver
import tiktoken

client = Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY"))
MODEL = "claude-sonnet-4-20250514"

# ============ Tính toán token ============
def count_tokens(text: str) -> int:
    enc = tiktoken.encoding_for_model(MODEL)
    return len(enc.encode(text)) if text else 0

# ============ State ============
class AgentState(TypedDict):
    user_id: str
    tenant_id: str
    task: str
    messages: Annotated[list[dict], add]
    long_term_facts: Annotated[list[str], add]
    active_skills: list[str]
    iteration: int
    status: str

# ============ Long-term memory ============
class MemoryStore:
    def __init__(self, db_path: str = "memory.db"):
        self.db_path = db_path
        self._init()

    def _init(self):
        conn = sqlite3.connect(self.db_path)
        c = conn.cursor()
        c.execute("""CREATE TABLE IF NOT EXISTS facts (
            id TEXT PRIMARY KEY,
            user_id TEXT NOT NULL,
            fact TEXT NOT NULL,
            timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,
            importance REAL DEFAULT 0.5
        )""")
        conn.commit()
        conn.close()

    def write(self, user_id: str, fact: str, importance: float = 0.5):
        """Ghi fact (nếu chưa có tương tự thì thêm)."""
        conn = sqlite3.connect(self.db_path)
        c = conn.cursor()

        # Check duplicate
        c.execute("SELECT id FROM facts WHERE user_id = ? AND fact LIKE ?",
                 (user_id, f"%{fact[:50]}%"))
        existing = c.fetchone()

        if existing:
            c.execute("UPDATE facts SET importance = MAX(importance, ?) WHERE id = ?",
                     (importance, existing[0]))
        else:
            fact_id = str(uuid.uuid4())
            c.execute("INSERT INTO facts (id, user_id, fact, importance) VALUES (?, ?, ?, ?)",
                     (fact_id, user_id, fact, importance))

        conn.commit()
        conn.close()

    def search(self, user_id: str, query: str, top_k: int = 3) -> list[str]:
        """Tìm fact liên quan (simple substring, Buổi 5 thêm embedding)."""
        conn = sqlite3.connect(self.db_path)
        c = conn.cursor()
        c.execute("""SELECT fact FROM facts WHERE user_id = ?
                     ORDER BY importance DESC LIMIT ?""",
                 (user_id, top_k))
        facts = [row[0] for row in c.fetchall()]
        conn.close()
        return facts

memory_store = MemoryStore()

# ============ Skill library ============
SKILLS = {
    "db": """# DATABASE SKILL
- Use WHERE clause always
- Show EXPLAIN if query complex
- Aggregate if >100 rows""",

    "report": """# REPORT SKILL
1. Executive summary (1 para)
2. Key metrics (table)
3. Analysis
4. Recommendation""",
}

def get_active_skills(task: str, budget: int = 10000) -> str:
    """Select skills based on task keywords."""
    active = []
    total = 0

    for skill_name, skill_text in SKILLS.items():
        if skill_name in task.lower():
            tokens = count_tokens(skill_text)
            if total + tokens <= budget:
                active.append(skill_text)
                total += tokens

    return "\n\n".join(active)

# ============ Context builder ============
def build_context(state: AgentState, token_limit: int = 200000) -> dict:
    """Build context with token budgeting."""

    user_id = state["user_id"]
    task = state["task"]

    # System prompt
    system = """Bạn là Operations Agent. Dùng tools để verify.
    Luôn kiểm tra: data có đủ trả lời không? Con số hợp lý không?"""

    system_tokens = count_tokens(system)

    # Runtime state
    runtime = {
        "user_id": user_id,
        "tenant_id": state["tenant_id"],
        "task": task,
        "request_id": str(uuid.uuid4()),
    }
    runtime_tokens = count_tokens(json.dumps(runtime))

    # Long-term memory (search)
    facts = memory_store.search(user_id, task, top_k=3)
    facts_text = "\n".join(f"- {f}" for f in facts)
    facts_tokens = count_tokens(facts_text)

    # Skills
    skills = get_active_skills(task, budget=10000)
    skills_tokens = count_tokens(skills)

    # History (compress if needed)
    used_tokens = system_tokens + runtime_tokens + facts_tokens + skills_tokens
    history_budget = min(50000, token_limit - used_tokens - 5000)  # 5K buffer

    history = state.get("messages", [])
    history_tokens = count_tokens(json.dumps(history))

    if history_tokens > history_budget:
        # Keep last 3 messages
        history = history[-3:]
        history_tokens = count_tokens(json.dumps(history))

    # Build final context
    context_text = f"""{system}

## Long-term facts
{facts_text if facts_text else "None"}

## Skills
{skills if skills else "None"}

## Runtime
{json.dumps(runtime)}

## Conversation history
{json.dumps(history)}"""

    return {
        "system": system,
        "context_text": context_text,
        "history": history,
        "token_usage": {
            "system": system_tokens,
            "runtime": runtime_tokens,
            "facts": facts_tokens,
            "skills": skills_tokens,
            "history": history_tokens,
            "total": used_tokens + history_tokens,
        }
    }

# ============ Nodes ============
def planner(state: AgentState) -> dict:
    context = build_context(state)
    print(f"[planner] tokens used: {context['token_usage']['total']}")

    resp = client.messages.create(
        model=MODEL, max_tokens=512,
        system=context["system"],
        messages=[{"role": "user", "content": f"Plan for: {state['task']}"}]
    )

    plan = resp.content[0].text
    return {
        "messages": [{"role": "assistant", "content": plan}],
        "iteration": state.get("iteration", 0) + 1,
    }

def verifier(state: AgentState) -> dict:
    """Verify and optionally write to long-term memory."""
    passed = state["iteration"] >= 2  # Simple check

    if passed and state.get("messages"):
        # Extract a fact to remember
        last_msg = state["messages"][-1].get("content", "")
        if "important" in last_msg.lower():
            memory_store.write(state["user_id"], last_msg[:100], importance=0.7)

    return {
        "status": "success" if passed else "running",
    }

# ============ Build graph (simplified) ============
graph = StateGraph(AgentState)
graph.add_node("planner", planner)
graph.add_node("verifier", verifier)
graph.set_entry_point("planner")
graph.add_edge("planner", "verifier")
graph.add_edge("verifier", END)

conn = sqlite3.connect("lab_context.db", check_same_thread=False)
checkpointer = SqliteSaver(conn)
app = graph.compile(checkpointer=checkpointer)

# ============ Run ============
if __name__ == "__main__":
    state = {
        "user_id": "user_alice",
        "tenant_id": "acme",
        "task": "Analyze Q3 revenue. Format as db report.",
        "messages": [],
        "long_term_facts": [],
        "active_skills": [],
        "iteration": 0,
        "status": "running",
    }

    config = {"configurable": {"thread_id": "lab-context-001"}}

    for _ in range(2):
        for chunk in app.stream(state, config):
            for node, output in chunk.items():
                print(f"✓ {node}: {output.get('status', 'running')}")
                state.update(output)
```

## 6. Review (10 phút)

- 1-2 học viên demo context builder, chỉ ra token breakdown.
- Chốt: context không phải "dump mọi thứ vào", mà là **thiết kế, ưu tiên, cắt bỏ** theo budget.

### Câu hỏi kiểm tra cuối buổi

1. Với 200K token budget, nếu history đã dùng 50K, skill 10K, system 2.5K → còn bao nhiêu cho tool result?
2. Skill `report` chỉ nên kích hoạt khi nào? (Tên skill nên là gì để dễ detect?)
3. Multi-user system: nếu quên WHERE user_id = ?, hậu quả là gì?
4. History 100 turns tốn 120K token. Nên truncate hay summarize? Tại sao?
5. Long-term memory "user prefer JSON" có nên ghi cho mỗi conversation không? Tại sao?

### Theo 4 câu hỏi của khóa

| Câu hỏi   | Trả lời cho Buổi 4                                                                                                                                          |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Why?      | Context window hữu hạn. System prompt + history + memory + skills cạnh tranh. Thiết kế sai → overflow, cost cao, quality xấu, leak dữ liệu.                 |
| How?      | Token budgeting, priority ranking (system > task > history > memory > skills), compression (truncate/summarize), multi-user namespace (WHERE user_id).      |
| Failure?  | Context overflow → tool result bị cắt. Memory leak → user A thấy user B's fact. Skill sai version → model confuse. History không compress → latency + cost. |
| Evidence? | Token usage bảng, memory query log (isolation check), skill activation matrix, history size before/after compress.                                          |
