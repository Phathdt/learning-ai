## 1. Theory — Three Pillars of Observability (20 phút)

### 1.1 Tại sao cần observability cho agent?

Agent khác workflow ở chỗ không biết trước control flow. Khi user gọi API, agent có thể:

- Gọi model 5 lần (retry).
- Gọi tool A, B, C, D.
- Gọi retrieval.
- Đi vào infinite loop hoặc timeout.
- Có latency từ 500ms đến 5 phút.
- Cost từ $0.01 đến $1.00 mỗi request.

**Vấn đề**: Nếu user báo "response quá lâu" hoặc "result sai", code của engineer không thể biết:

- Là model hang?
- Tool return error?
- Retrieval không tìm thấy knowledge?
- Agent loop vô hạn?
- Hệ thống chuyển đổi model nào?

**Giải pháp**: Observability cho phép engineer "xem qua mắt" agent execution mà không cần insert `print()` vào code.

### 1.2 Ba trụ cột observability

| Trụ         | Định nghĩa                                                       | Ví dụ agent                                                        | Khi dùng                               |
| ----------- | ---------------------------------------------------------------- | ------------------------------------------------------------------ | -------------------------------------- |
| **Logs**    | Discrete event: "tool called", "error occurred", "context built" | `"INFO: tool_call_start name=search_db args={...} request_id=xyz"` | Điều tra incident, debug logic         |
| **Metrics** | Time-series aggregate: rate, latency, count                      | `agent_run_duration_seconds=2.5`, `model_token_count_total=450`    | Theo dõi trend, alert trên performance |
| **Traces**  | Causal chain: request → model → tool → result → final            | Span A (model), Span B (tool), Span C (verify), all linked         | Tái tạo execution path                 |

### 1.3 Structured logging cho agent

Log không phải text string. Log phải là **dict** với field có ý nghĩa:

```python
import logging
import json

# ❌ Tệ
logging.info(f"Tool called: {tool_name}")

# ✅ Tốt
logger.info("tool_call_started", extra={
    "request_id": "req-123",
    "user_id": "user-456",
    "session_id": "sess-789",
    "agent_run_id": "run-abc",
    "event": "tool_call_started",
    "tool_name": "search_db",
    "tool_args": {"query": "revenue Q4"},
})
```

**Core fields cho agent**:

1. **request_id** — HTTP request từ client (correlation ID)
2. **user_id** — User gọi API
3. **session_id** — Conversation session
4. **agent_run_id** — Execution của agent (có thể có nhiều runs mỗi session)
5. **event** — Nó là gì: `context_built`, `model_call_start`, `tool_call_completed`, `error`, ...
6. **latency_ms** — Mất bao lâu?
7. **status** — success, error, timeout, ...
8. **error** / **error_type** — Nếu fail
9. **metadata** — Bất kỳ thông tin khác (model, tool name, token count, ...)

### 1.4 Logs vs Traces

**Logs**: Một dòng riêng lẻ, không nhất thiết có liên kết.

```json
{"event": "model_call_start", "request_id": "req-123", "timestamp": "2026-09-27T10:00:00Z"}
{"event": "model_call_completed", "request_id": "req-123", "timestamp": "2026-09-27T10:00:02Z"}
{"event": "tool_call_start", "request_id": "req-123", "timestamp": "2026-09-27T10:00:02Z"}
```

**Traces**: Một tree cấu trúc, parent-child.

```
Trace ID: trace-123
├─ Span: HTTP request (root)
│  └─ Span: Agent run
│     ├─ Span: Model call (iteration 1)
│     │  └─ Span: OpenAI API
│     ├─ Span: Tool call (search)
│     │  └─ Span: DB query
│     └─ Span: Model call (iteration 2)
```

### 1.5 Span, Span ID, Trace ID, Parent ID

**Trace** = một user request từ start đến end. Có **Trace ID** duy nhất.

**Span** = một sub-task trong trace. Có:

- `span_id` — ID của span này
- `parent_span_id` — ID của span cha
- `trace_id` — ID của toàn bộ trace
- `name` — "model_call", "tool_call", ...
- `start_time`, `end_time` — khi nào chạy
- `attributes` — metadata (model name, tool name, ...)
- `events` — các sự kiện xảy ra trong span
- `status` — ok, error

Ví dụ:

```
Trace ID: trace-abc-123

Span: HTTP request
  span_id: span-1
  parent_span_id: None (root)
  duration: 3.5s

  ├─ Span: build_context
  │  span_id: span-2
  │  parent_span_id: span-1
  │  duration: 0.2s
  │
  ├─ Span: agent_loop_iter_1
  │  span_id: span-3
  │  parent_span_id: span-1
  │  duration: 2.0s
  │
  │  ├─ Span: model_call
  │  │  span_id: span-4
  │  │  parent_span_id: span-3
  │  │  duration: 1.5s
  │  │  attributes: {model: "claude-3-opus", input_tokens: 200}
  │  │
  │  │  └─ Span: OpenAI API
  │  │     span_id: span-5
  │  │     parent_span_id: span-4
  │  │     duration: 1.4s
  │  │
  │  └─ Span: tool_call (search)
  │     span_id: span-6
  │     parent_span_id: span-3
  │     duration: 0.3s
  │     attributes: {tool: "search_db", tool_status: "success"}
  │
  └─ Span: agent_loop_iter_2
     span_id: span-7
     parent_span_id: span-1
     duration: 1.0s
```

## 2. Deep Dive — OpenTelemetry & Agent Instrumentation (30 phút)

### 2.1 OpenTelemetry architecture

OpenTelemetry (OTel) là standard mở để instrument code:

```
┌─────────────────┐
│  Your Agent     │  (Code with OTel SDK)
│  (with tracer)  │
└────────┬────────┘
         │
         │ OTLP (OpenTelemetry Protocol)
         │
┌────────▼──────────────┐
│ OpenTelemetry         │  (Optional)
│ Collector             │  (aggregates, batches)
└────────┬──────────────┘
         │
    ┌────┴────┐
    │          │
┌───▼──┐  ┌──▼───┐
│Grafana  │  │Langfuse│
└────────┘  └───────┘
```

**Tracer**: Trong code agent, tạo span.

```python
from opentelemetry import trace

tracer = trace.get_tracer(__name__)

with tracer.start_as_current_span("model_call") as span:
    span.set_attribute("model", "claude-3-opus")
    response = client.messages.create(...)
```

**Exporter**: Gửi span tới backend (Grafana, Jaeger, Datadog, ...).

**Collector** (optional): Nhận span từ nhiều service, aggregate, filter, gửi tới backend.

### 2.2 Agent trace design

Agent trace phải capture:

1. **HTTP request span** (root)
   - User request details
   - Authentication info
   - Start trace tại FastAPI middleware

2. **Agent run span** (child of HTTP request)
   - Agent initialization
   - Termination reason (success, max_iteration, error)

3. **Agent loop iterations** (children of agent run)
   - Iteration count
   - Control flow decision

4. **Model call span** (child of iteration)
   - Model name, temperature, max_tokens
   - Input token count
   - Output token count
   - Latency

5. **Tool call span** (child of iteration)
   - Tool name
   - Tool arguments (hash nếu sensitive)
   - Result status (success, error, timeout)
   - Latency

6. **Retrieval span** (child of iteration or model_call)
   - Query
   - Chunks retrieved
   - Similarity scores
   - Latency

7. **Verification/evaluation span** (child of iteration)
   - Evaluator type
   - Score
   - Pass/fail

### 2.3 Correlation: Request ID → Trace ID → Spans

**Request ID** là gì client sinh. Nó là **Trace ID** trong OpenTelemetry.

```python
# FastAPI middleware
@app.middleware("http")
async def add_trace_context(request, call_next):
    request_id = request.headers.get("X-Request-ID") or str(uuid.uuid4())

    # Set trace context
    trace_context = trace.set_span_in_context(
        trace.get_current_span()
    )

    with trace.use_span(
        trace.span_context.SpanContext(
            trace_id=int(request_id.replace("-", ""), 16) % (2**64),
            ...
        )
    ):
        response = await call_next(request)

    response.headers["X-Request-ID"] = request_id
    return response
```

**Kết quả**: Grafana UI cho phép engineer:

1. Tìm request bằng request_id
2. Xem toàn bộ trace chain
3. Drill down vào từng span

### 2.4 Key metrics cho agent

Không phải aggregate toàn bộ thành một con số. Phải track **per-dimension**:

| Metric                               | Loại      | Dimensioni                          | Ý nghĩa                             |
| ------------------------------------ | --------- | ----------------------------------- | ----------------------------------- |
| `agent_request_count`                | Counter   | model, status (success/error), user | Bao nhiêu request                   |
| `agent_request_duration_seconds`     | Histogram | model, user                         | P50, P95, P99 latency               |
| `model_token_input_total`            | Counter   | model, user                         | Tổng input token                    |
| `model_token_output_total`           | Counter   | model, user                         | Tổng output token                   |
| `model_cost_usd_total`               | Counter   | model, user                         | Tổng cost                           |
| `tool_call_count`                    | Counter   | tool_name, status                   | Gọi tool bao nhiêu lần              |
| `tool_error_rate`                    | Gauge     | tool_name                           | % tool fail                         |
| `agent_success_rate`                 | Gauge     | None                                | % agent reach goal                  |
| `agent_max_iteration_breached_count` | Counter   | model                               | Bao nhiêu request hit max iteration |
| `retrieval_latency_seconds`          | Histogram | source (Qdrant, database, ...)      | Retrieval speed                     |

### 2.5 Correlation patterns

**Pattern 1: Trace → Logs**

Logs có `trace_id`. Tìm trace → click → xem logs của trace đó.

```python
logging.info("tool_completed", extra={
    "trace_id": current_span.context.trace_id,
    "span_id": current_span.context.span_id,
    "tool_name": "search",
    "status": "success"
})
```

**Pattern 2: Langfuse + OTel**

Langfuse track agent semantics (generations, spans theo agent logic).
OTel track system/infrastructure (latency, errors, resource usage).

```
Langfuse: "Agent run", "Model call", "Tool call", "Retrieval"
   ↓
OTel:     "HTTP span", "DB query span", "API call span", "Cache hit"
   ↓
Grafana:  Show both, correlate by trace_id
```

## 3. Deep Dive — Failure Investigation Workflow (Optional, 5 phút)

Khi user báo "response sai", engineer làm thế nào?

1. **Tìm request ID** từ response hoặc user cung cấp.
2. **Mở Grafana**, search trace by request ID.
3. **Xem trace tree**:
   - Model call took 2s (slow)?
   - Tool return unexpected result?
   - Loop iterate 10 times (infinite)?
   - Error xảy ra ở đâu?
4. **Click vào span bị lỗi**, xem:
   - Attributes (arguments passed)
   - Events (intermediate steps)
   - Error message
   - Stack trace
5. **Đối chiếu Langfuse**: Xem semantic trace (generation input/output).
6. **Kết luận**: Prompts cần update? Tool cần fix? Model hành vi?

```python
async def agent_endpoint(request: Request):

    with tracer.start_as_current_span("agent_request") as span:
        span.set_attribute("request_id", request_id)
        span.set_attribute("user_id", request.user.id)

        # Agent loop
        with tracer.start_as_current_span("agent_run") as agent_span:

        return result
```

## 6. Review & Discussion (10 phút)

### Presentation expectations

Học viên show:

1. **Langfuse dashboard** — trace của agent run (generation, tool calls)
2. **Grafana trace view** — span tree, correlations
3. **Failed request investigation** — explain span chain, identify root cause
4. **One metric** — show time-series for latency or error rate

### Questions to discuss

1. **Correlation challenge**: Nếu agent gọi multiple subagents, làm sao correlate traces?
   - _Answer_: Pass trace_id qua subagent, subagent create child span.

2. **Storage**: Trace data to lớn. Chi phí để store?
   - _Answer_: Use sampling (10% traffic), only store failed traces, TTL 7 days.

3. **Privacy**: Sensitive data trong spans (PII, API keys)?
   - _Answer_: Never log full values. Hash sensitive data, use attribute keys only.

4. **Real-time**: Dapat thấy trace real-time hay chỉ sau khi request end?
   - _Answer_: OTLP batch theo mặc định. Configure `BatchSpanProcessor(batch_timeout=1000)` để near-real-time.

## Appendix: Code Template

### FastAPI + OTel setup

```python
from fastapi import FastAPI, Request
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
from opentelemetry.instrumentation.fastapi import FastAPIInstrumentor
from opentelemetry.instrumentation.requests import RequestsInstrumentor
import logging
import json
import uuid
from pythonjsonlogger import jsonlogger

# Setup OTel
otlp_exporter = OTLPSpanExporter(
    endpoint="https://your-grafana-tempo:4317"
)
trace_provider = TracerProvider()
trace_provider.add_span_processor(BatchSpanProcessor(otlp_exporter))
trace.set_tracer_provider(trace_provider)

# Setup logging
logger = logging.getLogger()
handler = logging.StreamHandler()
handler.setFormatter(jsonlogger.JsonFormatter())
logger.addHandler(handler)

app = FastAPI()

# Auto-instrument
FastAPIInstrumentor.instrument_app(app)
RequestsInstrumentor().instrument()

tracer = trace.get_tracer(__name__)

# Agent execution
@app.post("/v1/agent/run")
async def agent_endpoint(request: Request, body: dict):
    request_id = request.headers.get("X-Request-ID") or str(uuid.uuid4())

    with tracer.start_as_current_span("agent_request") as span:
        span.set_attribute("request_id", request_id)

        with tracer.start_as_current_span("agent_run") as agent_span:
            # ... run agent
            pass

        logging.info("agent_request_completed", extra={
            "request_id": request_id,
            "trace_id": format(span.get_span_context().trace_id, '032x'),
```
