## 1. Theory — Cloud Architecture và Stateless Runtime (20 phút)

### 1.1 Tại sao Cloud Run

Buổi 13, chúng ta chạy agent stack local: `docker-compose up`. Để production:

- Laptop không chạy 24/7.
- Scaling thủ công: mỗi request lớn hơn → lỗi.
- Không có monitoring, logs, SSL certificate.
- Data loss nếu machine die.

**Cloud Run** giải quyết: serverless container platform, auto-scale 0 → N, pay-per-request.

### 1.2 Cloud architecture cho agent

```text
Internet (HTTPS)
    ↓
   [Load Balancer]
    ↓
Cloud Run Service (agent-api)
    ├── Instance 1 (auto-scaled)
    ├── Instance 2
    └── Instance N
         ↓
    ┌────┴────┬────────┬──────────┐
    ↓         ↓        ↓          ↓
   LLM    Qdrant   Database   Langfuse
 Provider           (Cloud     (SaaS)
(Anthropic)        SQL/Firestore)
```

Mỗi mũi tên là một connection. Agent chạy stateless: mỗi request độc lập, không giữ state ở instance.

### 1.3 Stateless vs Stateful

| Khía cạnh               | Stateless (Cloud Run)                      | Stateful (Compute Engine)    |
| ----------------------- | ------------------------------------------ | ---------------------------- |
| **Instance lifecycle**  | Ephemeral, auto-restart                    | Persistent, manual restart   |
| **Request flow**        | N requests → N instances (scale 0→1000)    | M instances fixed            |
| **Scaling**             | Per-request, auto, cost-effective          | Manual, pre-provisioned      |
| **Latency**             | Cold start 1-5 giây (lần đầu)              | Instant (always running)     |
| **Cost**                | Pay-per-request, vCPU×duration             | Fixed monthly per instance   |
| **Session persistence** | Không (state lưu ở database/session store) | Có thể lưu ở instance memory |

**Quy tắc**: Nếu request có context dài (conversation, intermediate state), state phải ở **database hoặc session store** (Redis, Firestore), không ở instance memory.

Buổi 14, agent chạy stateless: mỗi `/agent/run` request gửi task → Cloud Run instance xử lý → store result ở database (session, checkpoint, memory) → return.

### 1.4 Cloud Run concepts

| Khái niệm         | Ý nghĩa                                   | Ví dụ                                                      |
| ----------------- | ----------------------------------------- | ---------------------------------------------------------- |
| **Service**       | Named endpoint, public hoặc private       | `https://agent-api-xyz.run.app`                            |
| **Revision**      | Immutable snapshot: code version + config | `agent-api@v5` (traffic 100%), `agent-api@v4` (0%)         |
| **Traffic split** | % request đến từng revision               | v5: 80%, v4: 20% (canary)                                  |
| **Concurrency**   | Max concurrent requests per instance      | 10 (mặc định), instance auto-scale nếu queue > concurrency |
| **Memory**        | RAM per instance                          | 512 MB (min) → 32 GB (max)                                 |
| **Timeout**       | Max request duration                      | 3600s (1 giờ)                                              |
| **Cold start**    | Lần đầu instance → request                | ~1-5 giây (phụ thuộc image size, startup code)             |

### 1.5 Request flow và scaling

```text
Request 1 → Cloud Run
            ↓
         Instance A (warm)
            ↓
          Process → Response (< 1 giây)

Request 2 → Cloud Run (1ms sau Request 1)
            ↓
         Instance A (busy)
            ↓
         Autoscaler checks: concurrency = 2, max = 10
            ↓
         Queue request (< 1 giây)

Request 100 → Cloud Run (spike)
            ↓
         Autoscaler checks: concurrency = 10, queue > 10
            ↓
         Launch Instance B, C, D (cold start 2-5 giây)
            ↓
         Process in parallel
```

**Insight**: Nếu agent request lâu (> 3 phút), nên chuyển sang background job (Cloud Tasks hoặc Pub/Sub + Workers) thay vì synchronous Cloud Run (Buổi 19).

## 2. Deep Dive — Secrets, Service Account, Logging, Revisions (30 phút)

### 2.1 Service Account và IAM

Cloud Run service chạy dưới một **service account** (identity). Service account có permissions để gọi external services.

Ví dụ:

- Gọi LLM provider API (Anthropic) → cần API key.
- Query Qdrant (nếu ở Cloud) → cần credentials.
- Write logs → tự động (Cloud Run identity có permission).

**Tạo service account**:

```bash
gcloud iam service-accounts create agent-sa \
  --display-name="Agent service account"

# Grant permissions
gcloud projects add-iam-policy-binding PROJECT_ID \
  --member="serviceAccount:agent-sa@PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/logging.logWriter"

gcloud projects add-iam-policy-binding PROJECT_ID \
  --member="serviceAccount:agent-sa@PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/cloudsql.client"  # If using Cloud SQL
```

Deploy Cloud Run với service account:

```bash
gcloud run deploy agent-api \
  --image gcr.io/PROJECT_ID/agent-api:latest \
  --service-account agent-sa@PROJECT_ID.iam.gserviceaccount.com
```

### 2.2 Secret Manager

**Không làm**:

```dockerfile
# ❌ Secret lộ trong image layer
ENV ANTHROPIC_API_KEY="sk-xxx"
```

**Cách đúng**: Google Secret Manager.

Tạo secret:

```bash
echo -n "sk-ant-xxx" | gcloud secrets create anthropic-api-key --data-file=-

# Hoặc từ file
gcloud secrets create db-password --data-file=/path/to/password
```

Grant service account access:

```bash
gcloud secrets add-iam-policy-binding anthropic-api-key \
  --member="serviceAccount:agent-sa@PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"
```

**Sử dụng trong Cloud Run**: Mount secret as environment variable:

```bash
gcloud run deploy agent-api \
  --image gcr.io/PROJECT_ID/agent-api:latest \
  --set-env-vars ANTHROPIC_API_KEY=/run/secrets/anthropic-api-key \
  --update-secrets anthropic-api-key=/run/secrets/anthropic-api-key:latest
```

Hoặc programmatically:

```python
from google.cloud import secretmanager

def get_secret(secret_id, version_id="latest"):
    client = secretmanager.SecretManagerServiceClient()
    name = f"projects/PROJECT_ID/secrets/{secret_id}/versions/{version_id}"
    response = client.access_secret_version(request={"name": name})
    return response.payload.data.decode("UTF-8")

api_key = get_secret("anthropic-api-key")
```

### 2.3 Environment variables

Cloud Run environment variables không encrypt (visibility công khai). Dùng cho config, không secrets.

```bash
gcloud run deploy agent-api \
  --set-env-vars \
    LOG_LEVEL=INFO,\
    DATABASE_URL=postgresql://...,\
    QDRANT_URL=http://qdrant:6333,\
    MAX_ITERATIONS=10
```

Hoặc từ `.env` file:

```bash
gcloud run deploy agent-api \
  --image gcr.io/PROJECT_ID/agent-api:latest \
  --env-vars-file .env.yaml
```

`.env.yaml`:

```yaml
DATABASE_URL: postgresql://user:pass@cloud-sql:5432/db
QDRANT_URL: http://qdrant.internal:6333
LOG_LEVEL: INFO
```

### 2.4 Logging

Cloud Run tự capture stdout/stderr → Cloud Logging.

Structured logging (JSON):

```python
import json
import logging

logging.basicConfig(
    level=logging.INFO,
    format='%(message)s'
)

logger = logging.getLogger(__name__)

# Log structured
logger.info(json.dumps({
    "request_id": "req-123",
    "user_id": "user-456",
    "event": "agent.completed",
    "latency_ms": 1240,
    "tokens": {"input": 500, "output": 200},
    "cost_cents": 5
}))
```

Query logs:

```bash
# Real-time tail
gcloud logging read "resource.type=cloud_run_revision" --limit 50 --follow

# Filter by service
gcloud logging read "resource.type=cloud_run_revision AND resource.labels.service_name=agent-api" --limit 100

# Filter by severity
gcloud logging read "resource.type=cloud_run_revision AND severity=ERROR" --limit 50
```

### 2.5 Revisions và Traffic Split

Mỗi deploy tạo revision baru. Cloud Run lưu toàn bộ lịch sử.

```bash
# Deploy revision mới
gcloud run deploy agent-api \
  --image gcr.io/PROJECT_ID/agent-api:v2 \
  --revision agent-api-v2

# List revisions
gcloud run revisions list --service agent-api

# Traffic split: v2 (80%), v1 (20%) — canary deployment
gcloud run services update-traffic agent-api \
  --to-revisions agent-api-v2=80,agent-api-v1=20

# Instant rollback: v1 (100%)
gcloud run services update-traffic agent-api \
  --to-revisions agent-api-v1=100
```

## 3. Demo — Build, Push, Deploy (15 phút)

### 3.1 Build image locally

```bash
cd agent/

# Build with tag
docker build -t gcr.io/PROJECT_ID/agent-api:1.0 .

# Test locally
docker run -p 8000:8000 \
  -e ANTHROPIC_API_KEY=$ANTHROPIC_API_KEY \
  gcr.io/PROJECT_ID/agent-api:1.0

# Verify
curl http://localhost:8000/health
```

### 3.2 Push to Artifact Registry

```bash
# Enable API
gcloud services enable artifactregistry.googleapis.com

# Create repository (if not exists)
gcloud artifacts repositories create agent-repo \
  --repository-format=docker \
  --location=us-central1

# Auth Docker to push
gcloud auth configure-docker us-central1-docker.pkg.dev

# Tag image
docker tag gcr.io/PROJECT_ID/agent-api:1.0 \
  us-central1-docker.pkg.dev/PROJECT_ID/agent-repo/agent-api:1.0

# Push
docker push us-central1-docker.pkg.dev/PROJECT_ID/agent-repo/agent-api:1.0

# Verify
gcloud artifacts docker images list \
  us-central1-docker.pkg.dev/PROJECT_ID/agent-repo
```

### 3.3 Deploy to Cloud Run

```bash
# Enable API
gcloud services enable run.googleapis.com

# Deploy
gcloud run deploy agent-api \
  --image us-central1-docker.pkg.dev/PROJECT_ID/agent-repo/agent-api:1.0 \
  --platform managed \
  --region us-central1 \
  --memory 512Mi \
  --cpu 1 \
  --timeout 600 \
  --concurrency 10 \
  --allow-unauthenticated \
  --set-env-vars LOG_LEVEL=INFO \
  --update-secrets ANTHROPIC_API_KEY=anthropic-api-key:latest
```

**Output**:

```
Service [agent-api] revision [agent-api-20240927-xxxxx] has been deployed
and is serving 100 percent of traffic.
Service URL: https://agent-api-xyz.run.app
```

### 3.4 Test public URL

```bash
SERVICE_URL="https://agent-api-xyz.run.app"

# Health check
curl $SERVICE_URL/health

# Run agent
curl -X POST $SERVICE_URL/agent/run \
  -H "Content-Type: application/json" \
  -d '{"task": "explain cloud run"}'
```

## 4. Lab — Full Deployment Workflow (45 phút)

### 4.1 Setup GCP project

```bash
# Set project
export PROJECT_ID="my-agent-project"
gcloud config set project $PROJECT_ID

# Enable APIs
gcloud services enable \
  run.googleapis.com \
  artifactregistry.googleapis.com \
  secretmanager.googleapis.com \
  logging.googleapis.com \
  sqladmin.googleapis.com  # If using Cloud SQL
```

### 4.2 Create service account

```bash
# Create
gcloud iam service-accounts create agent-sa \
  --display-name="Agent service account"

# Grant permissions
for role in \
  roles/logging.logWriter \
  roles/cloudsql.client \
  roles/secretmanager.secretAccessor
do
  gcloud projects add-iam-policy-binding $PROJECT_ID \
    --member="serviceAccount:agent-sa@$PROJECT_ID.iam.gserviceaccount.com" \
    --role="$role"
done
```

### 4.3 Create secrets

```bash
# Anthropic API key
echo -n "$ANTHROPIC_API_KEY" | gcloud secrets create anthropic-api-key --data-file=-

# Grant service account access
gcloud secrets add-iam-policy-binding anthropic-api-key \
  --member="serviceAccount:agent-sa@$PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"

# Database password (if needed)
echo -n "postgres-password-here" | gcloud secrets create db-password --data-file=-
gcloud secrets add-iam-policy-binding db-password \
  --member="serviceAccount:agent-sa@$PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"
```

### 4.4 Build and push image

```bash
# Build locally
docker build -t gcr.io/$PROJECT_ID/agent-api:1.0 agent/

# Configure Docker auth
gcloud auth configure-docker us-central1-docker.pkg.dev

# Create Artifact Registry repository
gcloud artifacts repositories create agent-repo \
  --repository-format=docker \
  --location=us-central1

# Tag
docker tag gcr.io/$PROJECT_ID/agent-api:1.0 \
  us-central1-docker.pkg.dev/$PROJECT_ID/agent-repo/agent-api:1.0

# Push
docker push us-central1-docker.pkg.dev/$PROJECT_ID/agent-repo/agent-api:1.0
```

### 4.5 Deploy to Cloud Run

```bash
IMAGE_URI="us-central1-docker.pkg.dev/$PROJECT_ID/agent-repo/agent-api:1.0"

gcloud run deploy agent-api \
  --image $IMAGE_URI \
  --platform managed \
  --region us-central1 \
  --memory 512Mi \
  --cpu 1 \
  --timeout 600 \
  --concurrency 10 \
  --service-account "agent-sa@$PROJECT_ID.iam.gserviceaccount.com" \
  --allow-unauthenticated \
  --set-env-vars \
    LOG_LEVEL=INFO,\
    DATABASE_URL=postgresql://...,\
    QDRANT_URL=http://qdrant.example.com \
  --update-secrets ANTHROPIC_API_KEY=anthropic-api-key:latest

# Get service URL
SERVICE_URL=$(gcloud run services describe agent-api --platform managed --region us-central1 --format="value(status.url)")
echo $SERVICE_URL
```

### 4.6 Test deployment

```bash
# Health check
curl $SERVICE_URL/health

# Run agent task
curl -X POST $SERVICE_URL/agent/run \
  -H "Content-Type: application/json" \
  -d '{"task": "Analyze cloud deployment"}'

# Check logs
gcloud logging read "resource.type=cloud_run_revision AND resource.labels.service_name=agent-api" \
  --limit 20 --format json
```

### 4.7 Deploy new revision (v2)

```bash
# Update code, build new image
docker build -t gcr.io/$PROJECT_ID/agent-api:2.0 agent/

# Push
docker tag gcr.io/$PROJECT_ID/agent-api:2.0 \
  us-central1-docker.pkg.dev/$PROJECT_ID/agent-repo/agent-api:2.0

docker push us-central1-docker.pkg.dev/$PROJECT_ID/agent-repo/agent-api:2.0

# Deploy v2 (without changing traffic — keep v1 at 100%)
gcloud run deploy agent-api \
  --image us-central1-docker.pkg.dev/$PROJECT_ID/agent-repo/agent-api:2.0 \
  --no-traffic  # Don't change traffic yet
```

### 4.8 Canary deployment

```bash
# List revisions
gcloud run revisions list --service agent-api --platform managed --region us-central1

# Split traffic: v2 (10%), v1 (90%) — canary
gcloud run services update-traffic agent-api \
  --platform managed \
  --region us-central1 \
  --to-revisions agent-api-v2=10,agent-api-v1=90

# Monitor metrics: error rate, latency
gcloud monitoring time-series list \
  --filter 'metric.type="run.googleapis.com/request_count"'

# If good, increase v2 to 50%
gcloud run services update-traffic agent-api \
  --to-revisions agent-api-v2=50,agent-api-v1=50

# Full rollout
gcloud run services update-traffic agent-api \
  --to-revisions agent-api-v2=100
```

### 4.9 Instant rollback

```bash
# List revisions
gcloud run revisions list --service agent-api

# Rollback to v1 (100%)
gcloud run services update-traffic agent-api \
  --to-revisions agent-api-v1=100

# Verify
curl $SERVICE_URL/health
```

## 5. Cost Control và Monitoring

### 5.1 Ước tính cost

Cloud Run: `$0.00001667 per vCPU-second + memory cost + request cost`.

Ví dụ 1000 requests/ngày, 512 MB, 2 giây mỗi request:

```
1000 requests × 2 seconds × 1 vCPU × $0.00001667 = $0.033/ngày ~ $1/tháng
Memory cost: minimal
Request cost: negligible
Total: ~$1-5/tháng
```

### 5.2 Set up budget alerts

```bash
gcloud billing budgets create \
  --billing-account=BILLING_ACCOUNT_ID \
  --display-name="Agent API monthly budget" \
  --budget-amount=50 \
  --threshold-rule=percent=80 \
  --threshold-rule=percent=100
```

## 6. Troubleshooting — Common Issues

| Issue                           | Lý do                               | Giải pháp                                       |
| ------------------------------- | ----------------------------------- | ----------------------------------------------- |
| **Cold start 5+ giây**          | Image quá lớn, startup code chậm    | Giảm image size (multi-stage), optimize startup |
| **503 Service Unavailable**     | Overload, autoscaler lag            | Increase concurrency, warm-up requests          |
| **Secret không accessible**     | Service account không có permission | Check IAM, grant secretmanager.secretAccessor   |
| **Database connection refused** | Private network, no access          | Use Cloud SQL Proxy hoặc Cloud SQL connector    |
| **Memory exceeded**             | Instance kill                       | Increase memory limit hoặc optimize code        |
| **Timeout (504)**               | Request > 600s                      | Use background job (Pub/Sub + Workers)          |
