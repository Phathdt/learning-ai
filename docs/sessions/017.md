1. Thiết kế AI Engineering Loop gồm 8 pha: Deploy → Collect → Identify → Add → Evaluate → Improve → Compare → Release.

7. Phân tích production traces (sampling 1-5%), nhận diện failure patterns.

## 1. Theory — AI Engineering Loop và Evaluation Tiers (20 phút)

### 1.1 Từ single eval sang continuous loop

Ở Buổi 7, học viên chạy evaluation **một lần** trước khi release: chọn 10 test case, chạy model, đánh giá thủ công. Kết quả?

| Vấn đề                      | Hậu quả                                            |
| --------------------------- | -------------------------------------------------- |
| Không đo quality regression | Release xấu hơn phiên bản trước                    |
| Không có feedback từ dùng   | Lỗi được phát hiện muộn (production) thay vì trước |
| Không trace được dòng lỗi   | Khó debug: "nguyên nhân regression là gì?"         |
| Evaluation là gating point  | Có lỗi thì block release, không có cách fix nhanh  |

**AI Engineering Loop** giải quyết bằng cách biến evaluation thành **continuous feedback process**:

```text
Deploy (v1)
 ↓
Collect Traces (production)
 ↓
Identify Failure (pattern)
 ↓
Add Dataset Case (vào golden dataset)
 ↓
Evaluate (baseline v1 vs candidate v2)
 ↓
Improve (fix prompt/tool/logic)
 ↓
Compare (baseline v1 vs candidate v2 trên regression suite)
 ↓
Release (v2) ← chỉ khi quality pass gate
 ↓
[Loop lại]
```

Mỗi pha 2–8 tuần xảy ra 1–2 lần/tuần. Release không lâu hơn 3 tuần. Theo [Databricks State of AI Report 2024](https://www.databricks.com/), team có continuous evaluation release **2.5× nhanh hơn** và chất lượng **15% tốt hơn** so với adhoc eval.

### 1.2 Offline evaluation: trước release

Offline = **không có production traffic**. Chạy trên dataset cố định (golden cases).

| Khía cạnh     | Mô tả                                                               |
| ------------- | ------------------------------------------------------------------- |
| **Khi nào**   | Trước khi deploy v2 tới staging hoặc production                     |
| **Data**      | Golden dataset: 10–50 test case đã annotate (ground truth)          |
| **Baseline**  | Model hiện tại (v1) chạy trên dataset                               |
| **Candidate** | Model mới (v2: prompt change, tool change, model swap) chạy dataset |
| **Metric**    | Task success, safety pass, latency, cost                            |
| **Decision**  | Candidate >= Baseline + threshold? → Release                        |

Ví dụ offline eval:

```python
# Baseline (v1)
baseline_results = []
for case in golden_dataset:
    output_v1 = run_agent_v1(case["input"])
    baseline_results.append({
        "case_id": case["id"],
        "success": output_v1 == case["expected"],
        "latency_ms": output_v1.latency_ms,
        "cost_usd": output_v1.cost
    })

baseline_metrics = {
    "task_success": sum(r["success"] for r in baseline_results) / len(baseline_results),
    "avg_latency_ms": mean([r["latency_ms"] for r in baseline_results]),
    "total_cost_usd": sum(r["cost_usd"] for r in baseline_results)
}

# Candidate (v2)
candidate_results = []
for case in golden_dataset:
    output_v2 = run_agent_v2(case["input"])
    candidate_results.append(...)

candidate_metrics = { ... }

# Compare
regression = baseline_metrics["task_success"] - candidate_metrics["task_success"]
if regression > 0.05:  # 5% drop is unacceptable
    BLOCK_RELEASE("Quality regression")
```

Regression suite ⊂ golden dataset. Regression suite là những cases khó nhất hoặc từng lỗi ở production → thêm vào dataset → dùng để ngăn regression tương tự.

### 1.3 Online evaluation: trong production

Online = **có production traffic**. Dùng real traces để detect quality issue nhanh.

| Khía cạnh     | Mô tả                                                     |
| ------------- | --------------------------------------------------------- |
| **Khi nào**   | Sau khi deploy v2 tới production (hoặc canary)            |
| **Data**      | Production traces; sampling 1–5% để không làm chậm        |
| **Metric**    | User feedback, error rate, latency spike, failure pattern |
| **Detection** | Failure rate > 2× baseline → alert                        |
| **Action**    | Investigate trace → add case vào dataset → prepare fix    |

Ba loại online signal:

1. **User feedback**: "Agent's answer không đúng" (explicit signal).
2. **Implicit signal**: "User không dùng output của agent" (no follow-up call).
3. **Automatic signal**: Latency spike (>3s), error rate spike (>5%), cost spike (>2× baseline).

Ví dụ online detection:

```python
# Langfuse đã log production traces với context
from langfuse import Langfuse

client = Langfuse(public_key="...", secret_key="...")

# Query: "Traces từ v2 trong 1 giờ qua, sample 5%"
trace_runs = client.trace.list(
    tags=["version:v2"],
    created_at={
        "from": (datetime.now() - timedelta(hours=1)).isoformat()
    },
    limit=1000,
    sample_rate=0.05
)

failures = []
for trace in trace_runs:
    # Tính: agent output có match user intent không?
    if not verify_correctness(trace):
        failures.append({
            "trace_id": trace.id,
            "input": trace.input,
            "output": trace.output,
            "reason": trace.metadata.get("failure_reason")
        })

failure_rate = len(failures) / len(trace_runs)
if failure_rate > 0.02:  # 2%
    ALERT(f"Failure rate {failure_rate:.1%} > baseline 1%")
    # Auto-add top 5 failures tới dataset để chuẩn bị fix
```

### 1.4 Quality gate design

Quality gate = **gating criterion** quyết định release/block.

Ba loại gate phổ biến:

| Gate                 | Công thức                                       | Ví dụ ngưỡng        |
| -------------------- | ----------------------------------------------- | ------------------- |
| **Task success**     | `task_success(v2) >= task_success(v1) - margin` | Không drop >5%      |
| **Safety pass rate** | `safety_pass(v2) >= 95%`                        | Giữ đảm bảo an toàn |
| **Regression count** | `regression_count(v2) <= max_allowed`           | Không hơn 2 case hư |

Cộng thêm:

| Gate               | Công thức                                      | Ý nghĩa             |
| ------------------ | ---------------------------------------------- | ------------------- |
| **Latency budget** | `p95_latency(v2) <= p95_latency(v1) * 1.2`     | Chậm tối đa 20%     |
| **Cost budget**    | `cost_per_call(v2) <= cost_per_call(v1) * 1.1` | Tốn tối đa 10% thêm |

Ví dụ quality gate config:

```python
QUALITY_GATES = {
    "task_success": {
        "metric": "task_success",
        "baseline_value": 0.92,
        "min_value": 0.87,  # không drop >5%

    "safety_pass_rate": {
        "metric": "safety_pass_rate",
        "min_value": 0.95,
        "block_release": True
    },
    "regression_count": {
        "metric": "regression_count",
        "max_value": 2,
        "block_release": True
    },
    "latency_p95": {
        "metric": "p95_latency_ms",

    }
}
```

## 2. Deep dive — Dataset, Baseline/Candidate, Comparison (30 phút)

### 2.1 Golden dataset structure

Golden dataset là hồn phách của evaluation. Thiết kế tốt → eval accurate, thiết kế xấu → eval naive.

```python
# Schema of one golden case
{
    "id": "case_001",
    "category": "incident_investigation",  # domain grouping
    "input": "Vì sao server bị timeout lúc 14:30 hôm qua?",
    "expected_output": {  # ground truth
        "structure": {
            "hypothesis": str,
            "evidence": [str],
            "action_items": [str]
        }
    },
    "difficulty": "hard",  # easy/medium/hard
    "source": "production_failure",  # adhoc/production_failure/synthetic
    "annotations": {
        "annotator": "engineer_alice",
        "timestamp": "2026-09-20T10:15:00Z",
        "confidence": 0.95  # 0–1, subjective
    },
    "metadata": {
        "agent_version": "v1",
        "tools_used": ["query_db", "grep_logs"],
        "regression": False  # đã từng fail không?
    }
}
```

Năm nguyên tắc xây dataset:

| Nguyên tắc                 | Ý nghĩa                                                                | Ví dụ                              |
| -------------------------- | ---------------------------------------------------------------------- | ---------------------------------- |
| **Coverage**               | Nhiều loại input (easy/hard, mỗi domain)                               | 60% easy, 30% medium, 10% hard     |
| **Ground truth precision** | Expected output là golden (có thể múi được từ production logs, oracle) | Trace từ manual verification       |
| **Regression case**        | Thêm case từ production failure để không repeat                        | Issue #123 → case_regression_123   |
| **Synthetic diversity**    | Thêm edge cases không được gặp ở production                            | Malformed input, boundary values   |
| **Up-to-date**             | Xóa/update case nếu requirement/domain thay đổi                        | Retire case nếu feature deprecated |

Quy tắc xây: bắt đầu 10–15 case (mix easy/hard), cộng 1–2 case mỗi tuần (từ production failures). Sau 6 tuần: 20–25 case solid foundation.

### 2.2 Evaluator types

Evaluator = hàm chấm điểm. Ba loại:

| Loại               | Triển khai                                              | Độ chính xác         | Tốc độ        |
| ------------------ | ------------------------------------------------------- | -------------------- | ------------- |
| **Exact/Code**     | `output == expected` hoặc regex match                   | Cao (100% tin tưởng) | Nhanh (<1ms)  |
| **Rule-based**     | If-else checks (e.g., "có N arguments?", "JSON valid?") | Trung bình           | Nhanh (<10ms) |
| **LLM-as-a-judge** | Gọi LLM để so sánh output với expected (grading)        | Cao nhưng cần tune   | Chậm (1–5s)   |

Ví dụ evaluator combination:

```python
def evaluate_case(output, expected):
    # 1. Exact match
    if output == expected:
        return {"pass": True, "reason": "exact_match"}

    # 2. Rule check: structure valid?
    try:
        parsed = json.loads(output)
        if "hypothesis" not in parsed or "evidence" not in parsed:
            return {"pass": False, "reason": "missing_fields"}
    except:
        return {"pass": False, "reason": "invalid_json"}

    # 3. LLM judge: semantic similarity
    judge = client.messages.create(
        model="claude-sonnet-4-20250514",
        max_tokens=100,
        messages=[{
            "role": "user",
            "content": f"""Compare:
            Expected: {expected['hypothesis']}
            Got: {parsed['hypothesis']}

            Are they semantically equivalent (both correct answer)? Answer YES or NO."""
        }]
    )

    is_pass = "YES" in judge.content[0].text.upper()
    return {"pass": is_pass, "reason": "llm_judge"}
```

### 2.3 Baseline vs Candidate

Baseline = model hiện tại (v1). Candidate = model mới (v2).

Comparison framework:

```python
class ExperimentRun:
    def __init__(self, name: str, agent_fn, dataset):
        self.name = name
        self.agent_fn = agent_fn
        self.dataset = dataset
        self.results = []

    def run(self):
        for case in self.dataset:
            try:
                output = self.agent_fn(case["input"])
                eval_result = evaluate_case(output, case["expected"])
                self.results.append({
                    "case_id": case["id"],
                    "output": output,
                    **eval_result
                })
            except Exception as e:
                self.results.append({
                    "case_id": case["id"],
                    "error": str(e),
                    "pass": False
                })

    def compute_metrics(self):
        passes = [r for r in self.results if r.get("pass")]
        return {
            "task_success": len(passes) / len(self.results),
            "total_cases": len(self.results),
            "failures": [r for r in self.results if not r.get("pass")]
        }

# Chạy
baseline_run = ExperimentRun("v1_baseline", agent_v1, golden_dataset)
baseline_run.run()
baseline_metrics = baseline_run.compute_metrics()

candidate_run = ExperimentRun("v2_candidate", agent_v2, golden_dataset)
candidate_run.run()
candidate_metrics = candidate_run.compute_metrics()

# So sánh
comparison = {
    "baseline": baseline_metrics,
    "candidate": candidate_metrics,
    "delta_task_success": candidate_metrics["task_success"] - baseline_metrics["task_success"],
    "regression_cases": [
        r for r in candidate_run.results
        if r["case_id"] in [b["case_id"] for b in baseline_run.results if b.get("pass")]
        and not r.get("pass")
    ]  # case nào pass ở v1 nhưng fail ở v2
}
```

### 2.4 Regression detection

Regression = "v2 worse than v1". Hai chiều:

1. **Regression count**: số case từng pass ở v1 nhưng fail ở v2.
2. **Regression delta**: metric (task_success) drop so với v1.

```python
def detect_regression(baseline_metrics, candidate_metrics, regression_threshold=0.05):
    delta = candidate_metrics["task_success"] - baseline_metrics["task_success"]

    if delta < -regression_threshold:
        return {
            "regression": True,
            "type": "metric_regression",
            "delta": delta,
            "severity": "block_release"
        }

    # Thêm: detailed failure analysis
    regression_cases = [
        case for case in candidate_results
        if (case_was_pass_before(case["case_id"]) and not case.get("pass"))
    ]

    if len(regression_cases) > 2:
        return {
            "regression": True,
            "type": "case_regression",
            "count": len(regression_cases),
            "severity": "block_release"
        }

    return {"regression": False}
```

### Bước 1: Chuẩn bị dataset và agents

```python
# demo_eval.py
import json
from anthropic import Anthropic

client = Anthropic()
MODEL = "claude-sonnet-4-20250514"

# Golden dataset (3 cases)
GOLDEN_DATASET = [
    {
        "id": "case_001",
        "input": "Tìm tất cả TODO comments trong repo",
        "expected_output": "Danh sách TODO, nhóm theo file, sắp xếp theo ưu tiên",
        "category": "code_analysis"
    },
    {
        "id": "case_002",
        "input": "Query DB lấy doanh thu ngày hôm nay theo khu vực",
        "expected_output": "Bảng doanh thu + tổng, có so sánh vs ngày hôm qua",
        "category": "data_analysis"
    },
    {
        "id": "case_003",
        "input": "Kết hợp 2 API response, format JSON, validate schema",
        "expected_output": "JSON hợp lệ, đầy đủ field, không lỗi parse",
        "category": "data_processing"
    }
]

# Agent v1 (baseline): minimal prompt
def agent_v1(task_input: str) -> str:
    resp = client.messages.create(
        model=MODEL,
        max_tokens=512,
        system="You are a helpful assistant. Complete the task.",
        messages=[{"role": "user", "content": task_input}]
    )
    return resp.content[0].text

# Agent v2 (candidate): improved prompt
def agent_v2(task_input: str) -> str:
    resp = client.messages.create(
        model=MODEL,
        max_tokens=512,
        system="""You are an operations intelligence assistant.
        Complete the task with precision and structure.
        Format output as:
        1. Summary (1–2 lines)
        2. Detailed results (bullet points)
        3. Next steps (if applicable)""",
        messages=[{"role": "user", "content": task_input}]
    )
    return resp.content[0].text

# Simple evaluator
def evaluate(output: str, expected: str) -> bool:
    # Rule: output length > expected length * 0.8 and contains key words
    keywords = expected.lower().split()[:3]  # first 3 words as signal
    output_lower = output.lower()
    matches = sum(1 for kw in keywords if kw in output_lower)
    return matches >= 2 and len(output) > 100
```

### 4.2 Bài tập: Create regression dataset → Baseline → Candidate → CI/CD gate

**Mục tiêu**: xây eval pipeline cho Operations Intelligence Agent.

**Yêu cầu**:

1. Tạo golden dataset 10–15 cases (mix easy/hard, multiple domains).
2. Implement baseline + candidate (2 prompt variant).
3. Chạy offline eval: compute task_success, latency, cost.
4. Detect regression: block release nếu task_success drop >5%.
5. Log results vào Langfuse experiment.
6. Tạo GitHub Actions workflow: run eval, post result as comment.
7. Thêm 3 production failure cases vào regression suite.

### 4.3 Skeleton code

```python
# lab_continuous_eval.py
import json, os, time, subprocess
from typing import Any
from datetime import datetime
from pathlib import Path
from anthropic import Anthropic
from langfuse import Langfuse

# ============ Setup ============
client = Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY"))
langfuse = Langfuse(
    public_key=os.getenv("LANGFUSE_PUBLIC_KEY"),
    secret_key=os.getenv("LANGFUSE_SECRET_KEY")
)
MODEL = "claude-sonnet-4-20250514"

# ============ Golden Dataset ============
GOLDEN_DATASET_PATH = "evaluation/golden_dataset.json"

def load_golden_dataset() -> list:
    """Load or create golden dataset."""
    if Path(GOLDEN_DATASET_PATH).exists():
        return json.load(open(GOLDEN_DATASET_PATH))

    # Synthetic dataset for lab
    return [
        {
            "id": "ops_001",

# ============ Evaluator ============
def evaluate_case(output: str, expected: str) -> dict:
    """Simple rule-based evaluator."""
    # Check: output contains key structure elements from expected
    checks = {
        "has_output": len(output.strip()) > 50,
        "has_structure": any(marker in output for marker in ["•", "-", ":", "\n"]),
        "contains_keywords": all(
            keyword.lower() in output.lower()
            for keyword in expected.split()[:2]
        )
    }

    passed = sum(checks.values()) >= 2

    return {
        "pass": passed,
        "checks": checks,
        "output_length": len(output)
    }

# ============ Run Experiments ============
class ExperimentRunner:
    def __init__(self, agent_fn, version_name: str, dataset: list):
        self.agent_fn = agent_fn
        self.version_name = version_name
        self.dataset = dataset
        self.results = []

    def run(self):
        print(f"\n=== Running {self.version_name} ===")
        for case in self.dataset:
            try:
                agent_output = self.agent_fn(case["input"])
                eval_result = evaluate_case(agent_output["output"], case["expected_output"])

                result = {
                    "case_id": case["id"],
                    "pass": eval_result["pass"],
                    "output_length": eval_result["output_length"],
                    "latency_ms": agent_output["latency_ms"],
                    "cost_usd": agent_output["cost_usd"],
                }

                self.results.append(result)
                status = "✓" if result["pass"] else "✗"
                print(f"{status} {case['id']}: {result['latency_ms']:.0f}ms, ${result['cost_usd']:.4f}")

            except Exception as e:
                print(f"✗ {case['id']}: ERROR {e}")
                self.results.append({
                    "case_id": case["id"],
                    "pass": False,
                    "error": str(e)
                })

    def compute_metrics(self) -> dict:
        passed = [r for r in self.results if r.get("pass")]
        latencies = [r["latency_ms"] for r in self.results if "latency_ms" in r]
        costs = [r["cost_usd"] for r in self.results if "cost_usd" in r]

        return {
            "version": self.version_name,
            "task_success": len(passed) / len(self.results) if self.results else 0,
            "total_cases": len(self.results),
            "failures": len(self.results) - len(passed),
            "avg_latency_ms": sum(latencies) / len(latencies) if latencies else 0,
            "p95_latency_ms": sorted(latencies)[int(len(latencies) * 0.95)] if latencies else 0,
            "total_cost_usd": sum(costs),
            "avg_cost_per_call": sum(costs) / len(costs) if costs else 0,
        }

# ============ Quality Gate ============
class QualityGate:
    def __init__(self, config: dict):
        self.config = config  # {"task_success": 0.87, ...}

    def check(self, baseline_metrics: dict, candidate_metrics: dict) -> dict:
        """Evaluate candidate against baseline + thresholds."""
        results = {
            "passed": True,
            "checks": {}
        }

        # Check: task_success
        baseline_success = baseline_metrics.get("task_success", 0)
        candidate_success = candidate_metrics.get("task_success", 0)
        min_success = self.config["min_task_success"]

        task_success_check = candidate_success >= min_success
        results["checks"]["task_success"] = {
            "passed": task_success_check,
            "baseline": baseline_success,
            "candidate": candidate_success,
            "threshold": min_success,
            "delta": candidate_success - baseline_success
        }
        if not task_success_check:
            results["passed"] = False

        # Check: latency
        baseline_latency = baseline_metrics.get("avg_latency_ms", 0)
        candidate_latency = candidate_metrics.get("avg_latency_ms", 0)
        max_latency_increase = self.config["max_latency_increase"]

        latency_check = candidate_latency <= baseline_latency * (1 + max_latency_increase)
        results["checks"]["latency"] = {
            "passed": latency_check,
            "baseline": baseline_latency,
            "candidate": candidate_latency,
            "max_allowed": baseline_latency * (1 + max_latency_increase),
        }
        # Note: latency is warn-only, not block

        # Check: cost
        baseline_cost = baseline_metrics.get("total_cost_usd", 0)
        candidate_cost = candidate_metrics.get("total_cost_usd", 0)
        max_cost_increase = self.config["max_cost_increase"]

        cost_check = candidate_cost <= baseline_cost * (1 + max_cost_increase)
        results["checks"]["cost"] = {
            "passed": cost_check,
            "baseline": baseline_cost,
            "candidate": candidate_cost,
            "max_allowed": baseline_cost * (1 + max_cost_increase),
        }
        # Note: cost is warn-only

        return results

# ============ Main ============
if __name__ == "__main__":
    dataset = load_golden_dataset()

    # Run baseline
    baseline_runner = ExperimentRunner(agent_v1, "v1_baseline", dataset)
    baseline_runner.run()
    baseline_metrics = baseline_runner.compute_metrics()

    # Run candidate
    candidate_runner = ExperimentRunner(agent_v2, "v2_candidate", dataset)
    candidate_runner.run()
    candidate_metrics = candidate_runner.compute_metrics()

    # Compare
    print(f"\n=== METRICS ===")
    print(f"Baseline: {baseline_metrics['task_success']:.0%} success, {baseline_metrics['avg_latency_ms']:.0f}ms, ${baseline_metrics['total_cost_usd']:.2f}")
    print(f"Candidate: {candidate_metrics['task_success']:.0%} success, {candidate_metrics['avg_latency_ms']:.0f}ms, ${candidate_metrics['total_cost_usd']:.2f}")

    # Quality gate
    gate = QualityGate({
        "min_task_success": max(0.87, baseline_metrics["task_success"] - 0.05),
        "max_latency_increase": 0.2,  # 20%
        "max_cost_increase": 0.1,     # 10%
    })

    gate_result = gate.check(baseline_metrics, candidate_metrics)
    print(f"\n=== QUALITY GATE ===")
    if gate_result["passed"]:
        print("✓ PASS: Ready to release")
    else:
        print("✗ BLOCK: Quality regression detected")
        for check_name, check_result in gate_result["checks"].items():
            if not check_result.get("passed"):
                print(f"  - {check_name}: FAILED")

    # Log to Langfuse
```

````yaml
      - name: Comment eval results

        uses: actions/github-script@v7

              owner: context.repo.owner,
              repo: context.repo.repo,

      - name: Block if quality regression
        run: |
          grep -q "✓ PASS" eval_results.txt || exit 1
````

## 6. Review (10 phút)

- 2–3 học viên trình bày golden dataset + quality gate config.
- Thảo luận: dataset nào cần thêm/bỏ? Ngưỡng task_success hợp lý?
- Chốt: continuous evaluation = feedback loop, không phải gating point duy nhất.

### Câu hỏi kiểm tra cuối buổi

1. AI Engineering Loop có 8 pha. Giai đoạn nào là offline, giai đoạn nào là online?
2. Baseline là gì? Candidate là gì? Tại sao cần so sánh?
3. Regression được phát hiện như thế nào? Đưa ra ví dụ 2 loại regression.
4. Quality gate có thể block release nếu điều kiện nào? Liệt kê ≥3.
5. Giả sử v2 task_success = 95%, v1 = 92%. Ngưỡng min_task_success = 87%. Có release được không?

### Theo 4 câu hỏi của khóa

| Câu hỏi   | Trả lời cho Buổi 17                                                                                                                |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Why?      | Manual evaluation sau mỗi release không scale. Continuous evaluation loop detect quality issue nhanh, cho phép rapid iteration.    |
| How?      | Golden dataset + baseline/candidate runner + comparison metrics + quality gate. Offline eval trước release, online monitoring sau. |
| Failure?  | Weak evaluator (false positive), dataset cũ (không cover regression), gate ngưỡng sai (quá chặt/quá lỏng), regression miss.        |
| Evidence? | Experiment result log, metric comparison, regression detection, quality gate pass/fail, Langfuse dashboard metrics.                |
